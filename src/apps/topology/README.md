# 网络拓扑 App

独立 LLDP 发现应用，使用 `platform.device_access` 的新 SSH 实现。原巡检不参与本应用。

- 入口：`/apps/topology`；队列：`app.topology`。
- 登录：本 App 保存一组默认用户名密码（按平台账号）；新建发现时可填写临时用户名密码，只用于本次任务、不保存。本次所有节点（包括新发现的邻居）使用同一组。
- 登录失败的节点弹窗输入新的用户名密码后只重试该节点；连接失败可重试或跳过；解析失败同样等待人工。
- 主机密钥首次连接自动记录（与 SSH 终端共用）；密钥变化时该节点停下，确认新指纹后重试。
- 原始证据在私有对象存储；观测、队列、人工处理与不可变快照在 App 自有数据库表。
- Comware/NX-OS 的线上采集和离线导入使用同一个版本化解析器。
- 在线发现默认逐节点自动识别平台；无需预先知道种子或邻居型号。版本探测与 LLDP 采集共用一次 SSH 登录，手工指定仅作用于该节点，不传递给邻居。
- 未识别、证据冲突、平台尚未适配的节点保留在任务中等待人工确认或跳过；不会用种子平台盲目发送 LLDP 命令。
- 模型基线是 RFC 8345 + SIMAP YANG -03（L2 用 RFC 8944、L3 用 RFC 8346）：每次任务把 LLDP/ARP/MAC/接口地址构建成 L2、L3 两个 network，快照保存标准树、每条链路的依据和画布视图，导出即标准树。所用模块、来源、摘要与 library 在 `resources/yang/`；SIMAP 为本地语法兼容副本。
- 终端定位：输入 IP 或 MAC，在快照中给出网关、接入设备和端口、VLAN，状态为已确认、共享网段、经过未采集设备、未找到、设备自身地址或 IP 冲突；每项附依据（MAC 表或 ARP 推断）和观测时间。复用构建器的接入判定，不登录设备。接口 `GET /snapshots/{id}/locate?q=`，知识问答工具 `topology__locate`。
- 首版是 LLDP 观测与数字孪生的数据基础；不把候选机箱等同于已确认资产，不提供仿真预测。
