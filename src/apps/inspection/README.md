# 网络巡检 App

`app.yaml` 自注册前端、API、Agent 工具、Celery 任务与恢复调度。
复制目录后按平台流程构建并重启服务、安装和启用，即可出现在工作台；不支持运行中热插拔。

- 入口：`/apps/inspection`；兼容 `/apps/patrol`。API：`/api/apps/inspection`。
- `backend/launch.py` / `submission.py`：幂等提交、冻结范围和资产、失败重试及重跑。
- `backend/online_tasks.py`：在线采集或经过核验的离线当前证据重放，随后依次归一化、变化检测、事件与检查项结论、报告。
- `backend/offline_tasks.py`：普通离线巡检和双周期历史比较；复用现有持久记录，不更新在线当前状态。
- `backend/patrol/`、`check_items/`：报告、原始证据交付、风险事件、当前证据核验等业务服务及报告资源。
- `frontend/`：巡检工作区、离线工作台适配、证据、风险、报告签发和包内 API 客户端。
- `access.py` / `lifecycle.py`：统一 App 使用权限、Worker 起跑再授权、执行与停用排空锁。

生产执行使用固定 Python 流程与 Celery，不创建 Workflow。历史 Workflow 仅用于读取和取消。
复用现有批次、冻结计划、PatrolRun、离线作业、报告记录以及 `netops.patrol` 队列；没有新任务表、节点引擎或队列。

设备库存、采集器、证据存储及解析/规则求值属于共享基础能力；规则发布资产通过既有运行时读取契约消费。
共享离线文件服务位于 `src/platform/evidence`，以服务端绑定的 purpose 区分规则样本与巡检，
因此规则样本不要求巡检 App 授权，巡检不要求规则编辑权限。原 core/gateway 路径保留兼容导入。

已有个人作业及文件所有权保留。独立核验人读取已提交的当前证据证明，不因此获得个人文件修改权限。
报告下载、旧 API 和 Agent 工具同样受巡检 App 授权约束；长连接定期重新检查授权。

停用先关闭准入和 Beat，再等待执行锁与请求释放，结算未完成任务，保留全部历史数据。
旧版本 Worker 必须先排空；代码升级后重建前端并更新安装摘要，再启用新版本。

## 离线巡检性能（1.2.5）

任务结果仅存阶段摘要和计数；观测、变化、事件从各自证据表读取，不再随每个阶段重复写入任务 JSON。
离线标准化按命令保存观测，报告分批读取观测并复用命令领域判定，避免同一规则配置被数十万次重复解析。
列表不读取任务结果大字段；作业权限检查只读取身份与工作区字段。页面仅在任务活动时轮询，错误后停止定时请求；新执行轮次不复用旧分析摘要。

旧任务的重复结果可使用 `python -m scripts.maintenance.compact_offline_job_results` 预览。
停用并排空巡检应用后，以 `--apply --backup-dir <目录>` 执行；每份原结果先备份为 gzip，再保留阶段摘要。
该操作不修改原始 CLI、解析快照、观测、变化、事件和历史采集时间，也不会把数据质量缺口改为成功。
1.1.0：`backend/diagnostics.py` 提供有界、只读、无 Workflow 关联查询的诊断契约。
HTTP 位于 `/api/apps/inspection/diagnosis/{search_devices,list_runs,list_events,list_snapshots,read_snapshot}`，
全部使用 POST JSON 查询参数并继承 inspection App 准入；Agent 工具调用相同函数。
默认每页10条、最大20条，可按设备、运行ID、采集时间范围查询；原文每次最多4000字符，先脱敏再分页。
不返回设备凭据、任意扩展属性或整份配置；不会触发采集、状态推进、报告生成或实时健康判断。
资产查询由 `src/platform/inventory/facts.py` 公共契约提供，助手不直接读取业务表。

1.2.0：巡检独立宽版工作区，与防火墙策略、资料管理统一视觉。任务中心合并在线与离线最近任务，支持搜索、来源筛选、任务摘要与结果跳转；五个巡检入口由侧栏导航，保留 URL 深链接。清除旧页面 null 文本，适配窄屏与键盘导航。业务执行、API 与任务队列保持原契约。

设备管理已拆为独立 App `/apps/device-management`。巡检通过自身只读资产 API 选择设备；仅设备维护入口检查 `device-management` App 授权。

1.2.4：离线详细 Excel 按检查项分表，直接导出数据库保存的 TextFSM Value 和完整记录；非结构化原文并列显示基线与当前数据。复用采集时记录集关联，不重跑字段映射。详细数据导出独立于 Word 结论组装，保留任务权限和周期校验。


## 巡检详情页面（1.2.6）

离线任务、在线批次、设备证据、判断依据、风险与反馈详情，以及报告内容验收和事实账本，
统一在工作区完整页面中打开。保留应用侧栏，顶部提供返回与任务操作；表格使用完整内容宽度。
查看下一层证据时保留上层页面状态，返回恢复筛选、选中页签与滚动位置；切换侧栏关闭详情。
离线任务继续使用 `offline_job_id` / `offline_job_tab` 深链接，支持刷新和浏览器前后退。
离线上传也使用完整页面；确认、签发等短操作继续使用对话框。此次调整不改变采集、变化统计、事件判定或报告契约。


1.2.7：巡检结果中的 CLI 对比按单条变化、观测或事件引用读取，直接查询该任务的原文快照，
不再为每一行组装全量报告。未触发事件的结构化变化也可查看原文。完整输出使用同一引用与摘要校验；
设备、命令、周期不一致时拒绝拼接，缺失证据明确提示。浏览器请求支持取消、20 秒超时和手动重试。

## 在线采集预览（1.2.9）

新建巡检先选择设备或分组，再点击“预览设备与命令”。列表展示每台设备名称、管理地址、有效命令集、按执行顺序排列的完整命令及预检状态。命令直接使用后端预检结果，检查项不会遮盖命令。
修改范围或表单后旧预览失效；尚在返回的旧请求不再覆盖新选择。发起时再次核对已预览的请求参数。
网络巡检不再提供设备管理和命令集配置入口，命令集在设备管理独立维护。

## 在线巡检创建工作页（1.2.10）

在线巡检创建复用巡检完整详情页，与应用侧栏和返回导航保持一致，不再使用大弹窗。
按选择设备、核对命令、发起巡检组织页面；设备与执行选项位于主区，旁侧展示本次采集摘要。正常环境检查折叠呈现，阻断项默认展开；底部操作区随滚动保持可见。
预检、命令顺序、范围失效保护及幂等发起沿用原实现，支持窄屏布局与减少动态效果设置。

删除旧平台模块页面、开关及巡检模块阻断提示。应用启停沿用 App 生命周期，正式巡检保留运行环境、连接及规则覆盖检查。

## 1.2.12

巡检结果使用结论摘要、关键指标和统一覆盖说明，移除重复的大面积状态色块。在线预检及离线现状核验复用轻量状态提示；加载失败保留错误标识和重试。结论语义、统计及下载流程不变。

## 1.3.0 容量改造

Windows 默认使用 6 个独立 solo 巡检 Worker，控制/心跳及 AI 队列独立。
检查域汇总按域预先分组；设备预检仅在新建巡检时请求，任务中心空闲时每分钟刷新。
真实在线 SSH 采集仍需在目标网络验收。
