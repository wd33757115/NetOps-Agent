# 资源台账（resource-ledger）0.4.0

一个应用里三本账：

- **IP 地址**：从总体地址资源（如 10.1.0.0/16）出发，按规划层级逐级划分（默认 地域 → 机房 → 网络区域 → 业务系统 → 子系统），在最末一级的网段里分配地址。
- **应用**：业务系统、子系统、主机（状态、环境、角色、IP、服务端口）。
- **专线**：运营商（含运营商网络、接入局端）、专线类型、共享风险、专线（A/Z 两端、互联地址、路由）；按在用专线检查站点韧性、计算故障影响。只记技术信息，不管合同和费用。

## 规划方式：按业务划分 IP

- 每个网段可以选一个层级，并绑定这一级对应的对象（某个地域、机房、网络区域、业务系统、子系统，或自定义层级的名称）；其余归属从上级网段继承。下级网段的层级必须比上级更深，可以跳过中间层级。
- 绑定必须一致：例如划给“西安”的网段下面不能出现北京的机房，划给某业务系统的网段下面只能有它自己的子系统。新建、修改、插入中间网段、调整层级时都会整棵子树检查。
- 划分：在一个网段上选层级和大小，取“下一个可用的 /N”，也可以改选其他空闲块。层级可以设默认大小，不设时按同级已有网段或上级大小建议。
- 规划层级可以改名、调整顺序、增加自定义层级；地域、机房、网络区域要从大到小，业务系统在子系统之上；有网段在用的层级不能删除。
- 网段的上下级不存储，按地址范围计算：CIDR 网段要么嵌套、要么不相交。路由域（VRF）只有一个“全局”时页面上不显示；多个路由域里可以有相同的私网网段。
- 不读取网络拓扑采集的数据，也不登记防火墙和安全域。生成防火墙策略时，下发到哪台防火墙、哪个安全域以防火墙策略应用的拓扑为准。

## 分配与主机

- 只在没有下一级的网段里分配地址；状态为“保留”“待回收”的网段不能分配。网络地址、广播地址（/31、/32 除外）、网关和保留范围内的地址不能分配。
- 可以先分配地址，以后再关联主机。主机的 IP 必须落在所属业务系统的网段里；主机有子系统时，地址所在网段如果划给了子系统，也必须是这个子系统。保存主机时，已分配的地址直接关联，未分配的地址当场分配。
- 主机的地址在网段里不能直接释放，要先在主机台账里移除；移除或删除主机后地址仍保留，需要时再释放。
- 改动网段的层级或归属、删除中间网段、改主机的业务系统时，都会检查已关联主机的地址是否还在自己的业务系统里。

## 专线

- 专线由“运营商 + 电路编号”确定。A 端是本方站点；Z 端是另一个站点、运营商网络，或者没有（只有一端的线路）。两端记设备接口、端口速率、配线、接入局端和地址。
- 运营商网络是运营商的 MPLS VPN、互联网等网络：专线的另一端不是本方站点时接在这里，接在同一个“站点间互通”网络上的站点可以经它互访。在“运营商与分类 → 运营商网络”里维护，新增专线时也可以直接输入名称新建；站点、运营商、局端、共享风险同样可以在专线表单里直接新建。
- 互联网段可以用网段规划里已有的最末一级网段，也可以从上级网段（如“互联地址”资源）自动划出 /30 或 /31。两端地址在其中分配（自动划出时两端地址可以留空，A 端、Z 端依次取前两个可用地址），归专线所有：网段规划里不能直接释放，在用专线的互联网段不能删除。专线改为“已拆除”或删除时，地址释放，互联网段转为待回收。
- 站点：扩展原来的机房，类型增加分支、门店、合作方；可以标为核心站点。
- 站点韧性：在用专线把站点和运营商网络连成图，只经过“站点间互通”的运营商网络和核心站点，算出每个站点到核心站点的路径。再逐一假设一处故障，列出会让站点断开的单点：运营商、运营商网络、局端、本端设备、单条专线从已录信息自动比对，光缆、管道、入户等共享风险靠手工标注。只陈述事实（到不了核心站点、有单点、没有发现单点、没有在用专线），不判断是否达标，是否需要整改由网络负责人结合业务判断。
- 故障影响：选一条专线、一家运营商、一个运营商网络、一个局端、一台设备或一项共享风险，算出哪些站点会断开、哪些只剩一条路，涉及的专线和报障电话，以及受影响站点上的业务系统（按主机地址所在的站点）。
- 只看台账：设备上实际配置的路由看不到，页面上写明了。

## 权限

- 有应用使用权即可查看；admin、operator 可以修改；Excel 批量导入只允许 admin。
- 所有写操作记入变更记录：谁、何时、改了哪个字段、旧值和新值（绑定的对象记名称）。

## 列表与分页

所有列表都显示分页栏、总条数，并可选每页 20、50、100 条。主机、专线、站点韧性和变更记录在服务端分页，其余列表一次取回后在页面上分页。

## Excel 导入与导出

模板含“站点”“网络区域”“业务系统”“网段”“保留范围”“IP 地址”“主机”“运营商”“运营商网络”“局端”“专线类型”“共享风险”“专线”十三张表和“说明”，按这个顺序导入；用不到的表可以删除。专线行按专线页面同样的规则写入；运营商、局端、专线类型、共享风险不存在时新建，站点和运营商网络要先建好。网段表用“层级”“归属”两列表达规划：地域和业务系统不存在时直接新建，机房、网络区域、子系统不存在时按上级网段继承的地域、机房、业务系统新建。预览和写入执行同一段逻辑，预览后回滚；只要有一行错误，写入就不会发生。“导出全部台账”按同样的格式导出，改完可以直接导回。

## 聊天工具

`agent.tools` 提供七个只读工具（带依据，经平台 MCP 提供给问答）：`find_systems`（按名称找业务系统及其网段和位置）、`list_hosts`（系统的主机、IP、服务端口）、`locate_ip`（地址在规划里的位置和使用它的主机）、`plan_access`（按台账拼出“源到目的”的防火墙策略申请行）、`find_circuits`（按电路编号、站点、设备、IP 查专线和报障方式）、`site_resilience`（站点到核心站点的路径和单点，只陈述事实）、`failure_impact`（假设一处故障的影响）。防火墙策略应用的 `draft_request` 动作通过 `plan_access` 生成申请表；台账里查不到的地址照常放行并在结果里说明。
