# 查阅产品文档集

## 先确认文档集和版本
1. 读 DOCSETS.md：列出资料库里的文档集（厂商、产品、软件版本、适用型号）和本轮已展开的目录。
2. 需要的文档集没有展开时，用它的 ID 调用 mcp__netops__open_docset 展开（每轮最多 3 个），它返回目录名。
   已展开的不用再调用。
3. 问题里的设备版本与文档集不一致或没说版本时，在回答里写明依据的版本；版本差异可能改变结论时先问用户。

## 每个文档集目录里有什么
- README.md：文档集说明和缺失提示。
- TOC.md：完整目录树，每行「缩进 - 标题 → pages/路径.md」。不要整个读，用 grep 找标题。
- index/commands.md：命令 | 视图 | 特性 | 命令格式首行 | 目录位置 | 文件
- index/alarms.md：告警名 | OID | 模块 | 类型 | 级别 | 文件
- index/logs.md：日志 ID | 模块 | 级别 | 文件
- pages/：每个页面一个文件。第 1 行是「> 位置：」（它在目录中的位置），第 2 行是类型、特性和原页面。

## 按问题类型查（路径都以文档集目录开头）
- 命令怎么用：grep `<目录>/index/commands.md`，再 read 命令页；格式、参数取值、视图以命令页为准。
- 告警：按告警名或 OID grep `<目录>/index/alarms.md`；日志按日志 ID（如 AAA/4/RDACCTDOWN）grep `<目录>/index/logs.md`；
  read 页面里的「可能原因」「处理步骤」。
- 某个功能怎么配：grep `<目录>/TOC.md` 找配置任务和配置举例，再 read；用到的命令回到命令页核对参数。
- 关键词不在标题里：grep `<目录>/pages`，看命中文件第 1 行的「位置」判断相关性，不要逐个打开。

## 读
- read 每次最多 100 行，长页面分段读；只读与问题相关的段落。
- 「> 说明：」「> 注意：」「> 警告：」引用块要读完，例外条件常在这里，
  例如管理口绑定 _management_vpn_ 时 ACL 规则要带 vpn-instance。
- 正文里的 ![图：…](figures/…) 是插图，图中内容不在正文里；需要时按下面「插图」一节识读。

## 插图
- 配置举例的组网图上才有设备名、互联接口、网关和接口地址、VLAN；正文常只写
  「本例中 interface1 代表 100GE1/0/1」。问题涉及设备怎么连、地址怎么规划、某台设备的接口或地址时，
  先 read 页面里那张图所在的行，再调用 mcp__netops__view_figure（page=页面路径，figure=figures/<文件>）。
- 返回的是视觉模型的识读，不是手册原文，可能有误：依据它写的内容要注明「据组网图」，
  并引用 [<目录>/figures/<文件>]；命令、参数、视图仍以正文为准。
- 每轮最多识读 4 张。硬件外观、气流、面板这类与问题无关的图不要识读。
- 识读不可用时，说明结论依赖这张图，请用户在资料库打开原页面查看。

## 引用
- 只引用读过的 pages/ 下的行，格式 [<目录>/pages/<路径>.md:L起始行-L结束行]。
  同一页面引用多次也每次写完整路径，不写「同上」。
- 识读过的插图引用为 [<目录>/figures/<文件>]。
- DOCSETS.md、README.md、TOC.md 和 index/ 只用于找页面，不能作为证据。

## grep 和 glob 的 path
- 文档集目录是链接进工作区的：grep、glob 必须把 path 设成 `<目录>`、`<目录>/pages` 或 `<目录>/index`，
  从工作区根目录（path 留空）搜不到其中的文件；把目录名写进 pattern 也不行。
- 例：grep pattern=hwBfdSessDown path=<目录>/index；glob pattern=*BGP*Threshold* path=<目录>/pages。
- grep 只接受 pattern/path/include；忽略大小写写成 (?i)。
- 不支持前后断言 (?!…)、(?<=…)；命令里的 [ ] { } | ( ) 要转义。
