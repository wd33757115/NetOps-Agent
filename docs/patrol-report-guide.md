# 巡检报告与证据

核对日期：2026-09-24。报告展示某次执行在特定资产版本和证据条件下的结果，不等同于设备永远健康，也不因“任务完成”自动取得生产结论资格。

## 一份冻结事实，多种交付物

在线批次的正式报告由不可变 ReportManifest 物化，再渲染所需格式。报告引用检查项、设备实现、运行包、样本和执行证据的版本或摘要，不临时读取最新 Parser 来改写过去结果。

| 交付物 | 内容 |
| --- | --- |
| Markdown | 可阅读的检查摘要与结论 |
| Word | 领导阅读的巡检报告 |
| Excel | 技术审计、明细、覆盖与依据 |
| JSON | 机器可读的报告事实 |
| ZIP | 证据及追溯材料 |

在线批次的各格式使用同一报告模型。离线巡检的 Word 使用本次分析事实和原文证据；详细数据 Excel 直接读取本次任务所选周期的数据库快照，不重新执行解析、字段映射或健康评估。

## 离线巡检详细数据 Excel

- 每个检查项一个工作表，以检查项名称命名。超过 Excel 的 31 字符限制或包含非法字符时做截断、替换，同名加序号。
- 结构化项列顺序为 `设备ID`、`命令`、数据库 `netops_command_snapshots.structured_json` 中的原始 TextFSM Value 名称。保留大小写、字段顺序、空值、前导零和大整数，不从观测表重建，不额外插入问题描述列。
- 同一命令产生多个检查项时，只使用采集时保存的 `source_record_set` 关联选择各自记录集，不执行适配器投影。CPU、内存等不会混入彼此工作表。
- 非结构化项为 `设备ID`、`命令`、`基线数据`、`当前数据`。保留完整原文并分行，变化行浅红提示。没有基线则基线留空，不解释为无变化。
- 重复采集的结构化记录全部保留；无法唯一配对的多份原文分别保留，并在导出说明中标明。
- 旧任务没有检查项关联的命令按命令名分表，保留数据并在导出说明中注明，不用当前目录猜测历史关联。解析为空、采集缺失和定义缺失同样列明。
- 样式参考 `patrol_tool_opt.py`：浅蓝表头、黑色细边框、紧凑行高，冻结表头及设备、命令列，支持筛选与横向滚动。
- 详细数据按钮、报告弹窗中的 Excel、证据 ZIP 共用同一渲染器。纯 Excel 导出不依赖 Word 结论和引用校验，但仍校验任务权限、完成状态和周期范围。

Inspection 1.2.4 验证：60 项后端报告相关测试、5 项前端下载相关测试通过；当前双周期任务的 1,940 条本期解析记录全部导出，23 个工作表（含导出说明）。浏览器 Word 请求返回 200，DOCX 可正常解包读取，证据 ZIP 包含新 Excel。原先反馈的 Word 失败未复现；修正了 Blob 下载链接立即释放的时序问题，并将导出校验错误转成可读响应。当前机器缺少 LibreOffice，未完成 Word 分页渲染检查。

## 结论资格

报告保留用途、数据完整度、可比性和执行阶段。生产当前巡检、离线历史对比、Parser 验证、规则回放与影子验证不能混为同一种结果。用途与来源事实由服务端校验，界面标签不能提升报告权限。

- 解析失败、缺少资产、缺少基线或口径不兼容，应显示对应原因。
- “首次观测”没有历史变化依据；“没有发现变化”不代表检查结果正常。
- 正常、风险、无法判断、不适用与信息性结果分别保留。
- 文本变化是证据事实；没有相应判断标准时不能推导为故障或恢复。
- 降级证据、未完成步骤和覆盖缺口不能被汇总数字隐藏。

报告 Claim Ledger 与投影快照用于约束结论可追溯性。新文案或新表格应消费现有报告投影，避免在前端另写一套判断逻辑。

## 下载与历史一致性

已附加的正式产物保存对象键和 SHA-256。读取与完整性检查需要验证对象可用且摘要匹配；缺失或被改写应报错，不静默拿新内容冒充原附件。按需渲染单个格式的接口无需生成其他四种文件。

旧 PatrolBatch 历史投影仍可能被历史任务和 Celery 消费。新 ReportManifest 路径替代了默认模型，但删除旧读取器前必须证明历史数据已经可读取，见[兼容退出登记](implementation/deprecations.yaml)。
