# 巡检报告与证据

核对日期：2026-09-06。报告展示某次执行在特定资产版本和证据条件下的结果，不等同于设备永远健康，也不因“任务完成”自动取得生产结论资格。

## 一份冻结事实，多种交付物

当前正式报告由不可变 ReportManifest 物化，再渲染所需格式。报告引用检查项、设备实现、运行包、样本和执行证据的版本或摘要，不临时读取最新 Parser 来改写过去结果。

| 交付物 | 内容 |
| --- | --- |
| Markdown | 可阅读的检查摘要与结论 |
| Word | 领导阅读的巡检报告 |
| Excel | 技术审计、明细、覆盖与依据 |
| JSON | 机器可读的报告事实 |
| ZIP | 证据及追溯材料 |

各格式由同一报告模型产生。Excel 使用完整审计渲染器；旧的未使用简版渲染器已移除。工作表与列随事实及报告投影变化，不用某次历史样例的固定工作表数量作为接口契约。

## 结论资格

报告保留用途、数据完整度、可比性和执行阶段。生产当前巡检、离线历史对比、Parser 验证、规则回放与影子验证不能混为同一种结果。用途与来源事实由服务端校验，界面标签不能提升报告权限。

- 解析失败、缺少资产、缺少基线或口径不兼容，应显示对应原因。
- “首次观测”没有历史变化依据；“没有发现变化”不代表检查结果正常。
- 正常、风险、无法判断、不适用与信息性结果分别保留。
- 文本变化是证据事实；没有相应判断标准时不能推导为故障或恢复。
- 降级证据、未完成步骤和覆盖缺口不能被汇总数字隐藏。

报告 Claim Ledger 与投影快照用于约束结论可追溯性。新文案或新表格应消费现有报告投影，避免在前端另写一套判断逻辑。

## 下载与历史一致性

已附加的正式产物保存对象键和 SHA-256。读取与完整性检查需要验证对象可用且摘要匹配；缺失或被改写应报错，不静默拿新内容冒充原附件。按需渲染单个格式的接口无需生成其他四种文件。

旧 PatrolBatch 历史投影仍可能被历史任务和 Celery 消费。新 ReportManifest 路径替代了默认模型，但删除旧读取器前必须证明历史数据已经可读取，见[兼容退出登记](implementation/deprecations.yaml)。
