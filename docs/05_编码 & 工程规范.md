# 编码与工程规范

核对日期：2026-09-06。工具配置以 [pyproject.toml](../pyproject.toml)、前端 package.json 和 CI 为准。

## 模块边界

- `src/gateway` 定义 FastAPI 接口；`web/django_backend` 负责浏览器认证、代理和用户数据。
- `src/core` 保存领域服务、执行和持久化协调；`src/infrastructure` 提供数据库与对象存储接入。
- `src/skills` 保存 Skill 定义及执行代码；`src/workflows` 保存插件化编排。
- `web/react_frontend` 承载当前业务 UI，App Registry 统一入口；不要重新引入旧侧栏或独立 Streamlit 页面。

字段转换、权限、报告资格等规则在服务端校验。前端展示不能成为唯一安全门禁；Worker 也不能通过跳过 API 失去作用域检查。

## Python

当前格式工具行宽为 100，Ruff 检查配置见 pyproject。改动遵循所在模块风格，避免无关的全仓库自动格式化。

新增代码优先明确输入输出类型和失败含义。领域异常通过 API 层映射，不用“捕获所有异常并返回空列表”掩盖失败。长任务进入适当 Worker 队列，保留幂等标识、执行状态和取消/恢复语义。

使用 `src.core.logging.get_logger` 记录稳定事件名和业务标识，日志上下文按 token 恢复。内部观测字段由 `strip_observability_keys` 等边界处理，不能混入 Skill CLI 参数。详见[日志](08_日志规范%20&%20日志字典.md)与[错误处理](09_错误码定义文档.md)。

## 前端

统一通过 API 服务层和 `utils/api.ts` 请求 BFF，使用 `ApiError` 解析错误。路由、菜单和 App 可见性共享权限条件；实际操作仍由服务端验证。

复用现有 Shell、响应式 hook、Ant Design 组件和领域状态模型。加载、空结果、失败与无权限应明确区分；异步任务入队后根据持久状态展示进度，不只等待一个长 HTTP 请求。

前端依赖安装使用 `npm ci`。`npm run check` 覆盖编码、lint、Vitest 和构建；浏览器回归单独执行。

## 变更与验证

修改 API、持久数据或版本契约时同步核对调用方、迁移与历史读取。测试验证真实行为和失败边界，不复制实现作断言，不因测试陈旧而放宽业务门禁。

全量测试与数据回放使用隔离环境，不能因为目录名是 unit 就假定不会访问数据库。命令与范围见[测试手册](测试手册.md)。

不提交 `.env`、密钥、运行日志或真实设备原文。修改控制在相关文件；删除实现前检查导入、动态注册、CLI、插件及持久化引用。
