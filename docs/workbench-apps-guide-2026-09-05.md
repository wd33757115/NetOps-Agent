# 工作台与巡检应用接入说明

日期：2026-09-05

## 入口与使用

左侧“工作台”进入 `/workbench`。首期提供“网络巡检”和“巡检规则生成”两个应用，桌面上双击打开，手机轻点打开。Dock 单击打开。

桌面图标可以拖动，落下后吸附到格子；拖到另一个普通应用交换位置，拖到文件夹加入文件夹。右上角或桌面右键可新建文件夹。文件夹点击展开，内部应用支持拖入、拖出、排序；解散文件夹将应用放回桌面。应用的“…”操作也提供移动和固定命令，供键盘和触屏操作。

Dock 支持固定、取消固定及排序，仅保存快捷引用。取消固定不删除桌面或文件夹中的应用。

工作台采用 macOS 风格的全屏桌面：蓝色山峦壁纸、顶部菜单与本地时钟、磨砂 Dock、应用图标和文件夹窗口。点击左上角 NetOps 打开系统导航；桌面与手机共用导航抽屉，隐藏历史对话。普通页面的折叠偏好按用户保存，不受工作台影响。Dock 悬停放大，文件夹展开和图标入场带轻量动画，遵循系统减少动态效果设置。

| 应用 | 路由 | 业务内容 |
|---|---|---|
| 网络巡检 | `/apps/patrol` | 在线巡检、离线巡检、风险与整改、质量反馈、批次结果与报告 |
| 巡检规则生成 | `/apps/patrol-rules` | 检查项目录、样本导入、现有规则资产生成/验证/审核/发布与运行资产 |
| 样本任务详情 | `/apps/patrol-rules/source-jobs/:jobId` | 现有 CLI 样本任务详情 |

旧的 `/devices?tab=patrol`、`/skills/parser` 及来源任务详情链接仍然可用，自动跳转时保留证据参数和 hash。设备管理和 Skill 管理仍然独立存在。

## 部署步骤

使用已有后端运行环境，从仓库根目录执行：

```sh
python web/django_backend/manage.py migrate bff
```

新增 Django 表 `bff_desktoppreference` 与已有用户一对一关联。此迁移不修改巡检、规则、报告业务表，不属于业务 Alembic 迁移。应先部署后端并执行迁移，再启用新前端。

前端在 `web/react_frontend` 安装依赖并构建：

```sh
npm install
npm run build
```

新增的直接依赖固定为 `@dnd-kit/core@6.3.1`、`@dnd-kit/sortable@10.0.0`。仓库当前不跟踪 npm/pnpm lock 文件，本次遵循现有约定。

`VITE_WORKBENCH_ENABLED` 默认启用。设置为 `false` 后重新构建，可隐藏工作台并将新应用路由映射回旧入口。回退不删除已保存布局或业务数据。

布局 API：

```text
GET /api/auth/me/desktop-layout/
PUT /api/auth/me/desktop-layout/
```

两个接口均要求有效登录 JWT。用户归属由后端认证结果确定，客户端不能指定其他用户。PUT 带上读取的 `revision`；版本冲突返回 409。JSON 格式由 `bff/views/desktop.py` 校验，响应遵循已有 BFF 封装。

## 保存与恢复

- 图标变更立即显示，600ms 防抖后串行保存。保存中再次修改会在前次请求结束后继续提交，不用旧响应覆盖新编辑。
- 保存失败时保留按用户隔离的本地草稿，并显示重试入口。
- 读取失败时不自动创建并覆盖服务器布局。
- 多标签页发生版本冲突时保留本地草稿，用户明确选择“加载最新布局”后才替换。
- 退出登录中止旧用户请求并清空内存状态；待同步草稿按账号隔离。
- 巡检批次 ID 和在线/离线子页保存在 URL，刷新可以恢复。未提交的设备选择、分组、工单号等范围信息保存在当前浏览器会话草稿中，成功创建巡检后清理。
- 从设备页发起巡检会携带所选设备或完整筛选条件，仍需现有预检与正式执行操作。

## 实现边界

应用注册与入口集中在 `web/react_frontend/src/apps/`。桌面只引用 appId，不保存业务 URL、图标或权限定义；新增业务 UI 完成后再注册应用。

巡检与设备管理共用 `DeviceOperationsWorkspace`，通过 mode 区分页面内容，查询和 mutation 保持单一实现。巡检应用隐藏设备 CRUD 工具栏，独立提供范围选择、执行和结果入口。这个阶段没有将该共享容器进一步拆成所有领域 hook；后续可继续按业务边界拆分，避免本次同时重写执行逻辑。

规则应用直接复用 `ParserControlTab` 及其工作区，保留 CheckItem 标准语义生成规则、样本验证解析映射的现有合同。迁移不自动生成规则、不绕过现有审批/发布门禁。

首期为单桌面、一层文件夹，不包含多窗口、嵌套文件夹或多桌面。防火墙策略生成尚未新增专用 UI。公文写作已追加独立应用，见 [公文工作台说明](./official-document-workspace-guide-2026-09-05.md)；原有图标位置和 Dock 保留。
