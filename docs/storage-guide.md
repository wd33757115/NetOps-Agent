# 网盘与对象存储

核对日期：2026-09-06。页面入口为 `/storage`，BFF 为 `/api/storage/`，内部 API 为 `/api/v1/storage`。

## 当前能力

网盘使用 PostgreSQL 的虚拟目录、文件元数据和团队关系组织 MinIO 对象。支持目录树、列表、上传、预览/下载、重命名、移动、复制、删除以及复制分享至团队。团队和成员管理由管理员操作。

个人目录按所有者授权，团队目录按成员及团队角色授权；平台 viewer 不能写入，团队 viewer 也不能写入。管理员有额外管理权限。目录根命名空间、文件归属和团队信息必须一致，不能只凭对象 key 前缀判断访问权。

源码入口：[storage_api.py](../src/gateway/storage_api.py)、[领域服务](../src/storage/)、[权限策略](../src/storage/permissions.py)、[StoragePage](../web/react_frontend/src/pages/StoragePage.tsx)。

## 上传与下载

1. `upload/init` 校验写权限、目标目录、声明大小与配额，创建 pending 元数据并返回预签名 PUT 地址。
2. 浏览器将文件上传到该地址。MinIO 外部地址必须可由浏览器访问，并允许实际前端来源的 CORS 请求。
3. `upload/complete` 再检查文件权限与目录范围，确认对象存在后转为 active。上传字节成功但确认失败时，不应把 pending 记录当作可用文件。

当前页面的预览和下载使用经过 BFF 的 `files/{id}/content`；后端也保留获取预签名下载地址的接口。网盘直传与应用产物下载是不同路径，不能把所有报告或公文导出都当作网盘上传流程。

对象 key 由服务端目录解析与命名逻辑生成，数据库保存引用。移动、重命名和旧 key 修复由领域服务处理，客户端不能任意提交其他用户的对象路径。

## 部署与维护

配置来自 `MINIO_ENDPOINT`、访问凭据、bucket 与外部地址等设置，见 [配置参考](07_系统配置说明.md)。浏览器直传需要匹配实际部署域名的 CORS；后端能够访问内部 `minio:9000` 不代表浏览器也能访问。

数据库迁移使用 Alembic，Django 用户已默认位于 PostgreSQL。旧方案中的自动 `create_all` 初始化和 SQLite 用户库说明不适用于默认部署。

备份必须包含 PostgreSQL 元数据与对应 MinIO 对象；只保留目录树无法恢复文件。对象引用、归属及完整性校验应随恢复一起验证。不要在代码清理中直接删除未确认归属的历史对象。

当前指南不承诺任意文件版本管理、回收站、分片上传或自动 RAG 索引；这些需要独立设计和验收。产品级公文版本与网盘文件版本不是同一机制。
