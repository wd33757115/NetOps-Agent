# 非结构化巡检与文本比较

核对日期：2026-09-06。配置和诊断输出可以采用文本检查；选择依据是检查项的业务含义，不是 TextFSM 是否生成成功。

## 当前检查项路径

检查项实现显式使用 `normalized_diff` 或 `hash_only`，绑定版本化 TextComparisonProfile。自动制作对这类实现准备文本比较配置，跳过 TextFSM/结构化 Projection。结构化检查项解析失败仍然是失败，不能自动换成文本比较来获得成功状态。

当前 Profile 支持：

| 模式 | 比较行为 |
| --- | --- |
| `ordered_lines` | 保留行顺序，比较规范化文本摘要 |
| `unordered_lines` | 排序后比较，忽略顺序；重复行仍保留在摘要中 |
| `hash_only` | 比较规范化摘要，不输出增删行 |

配置依次执行脱敏、规范化和忽略规则。结果保存 Profile 版本及摘要、前后文本摘要、可比性和有限预览。无基线时 `changed` 为未知，不是无变化。

增删行预览不是完整编辑脚本：当前实现按行是否存在生成预览，所以只有顺序或重复次数变化时，摘要可能变化而增删预览为空。不能用预览行数代替最终 `changed` 判断。

## 旧命令级文本变化

`patrol/unstructured_diff.py` 仍服务于已有命令级变化链，包含有序配置比较与滚动日志窗口。日志窗口采用多重集合差异，旧日志滚出窗口不等于故障恢复。

该路径与检查项 TextComparisonProfile 是不同的执行实现，不能直接互换配置字段，也不能把旧路径的滚动窗口能力当成每个新 Profile 的既有行为。新增检查项优先使用当前检查项路径；历史命令和报告保留原版本解释。

## 结果含义与证据

- 文本变化证明内容变化，没有对应标准时不能升级为故障事件。
- 敏感信息的脱敏规则会影响比较口径；报告应携带配置版本，不能隐去该差异。
- 截断、采集错误、不支持命令和身份不明需要按质量失败处理，不能作为正常空文本比较。
- 报告保留来源 Snapshot、时间、摘要和比较配置；按[报告用途](patrol-report-guide.md)限定结论。
