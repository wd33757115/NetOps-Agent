# 系统配置参考

核对日期：2026-09-06。配置字段及校验逻辑以源码为准；本页说明职责和排查方式，不复制一份容易过期的全量默认值表。

## 配置来源

| 组件 | 权威定义 | 生效方式 |
| --- | --- | --- |
| FastAPI / Worker / Beat | [Settings](../src/common/config.py) | 根目录 `.env` 加进程环境，进程重启后生效 |
| Django BFF | [Django settings](../web/django_backend/django_backend/settings.py) | 自身环境和 `.env` 读取逻辑 |
| React | [Vite 配置](../web/react_frontend/vite.config.ts) | `VITE_*` 在构建时写入前端资源 |
| Compose | [核心配置](../deployment/docker-compose.yml)及覆盖文件 | Compose 插值与容器 environment / env_file |

`.env.example` 是安装模板，实际部署值应保存在本机配置或部署密钥系统。Python 的 dotenv 默认不覆盖已有进程变量；修改文件但未重启，或被容器环境覆盖，都会导致“配置没生效”。不要将完整运行环境或密钥输出到排障记录。

## 常用配置组

| 范围 | 主要变量 | 核对要点 |
| --- | --- | --- |
| 模型 | `LLM_PROVIDER`、`LLM_MODEL`、`LLM_API_KEY`、`LLM_BASE_URL`，以及 Provider 专属变量 | 使用当前选定 Provider 的实际地址和认证；并非所有路径都只支持 DeepSeek |
| Parser | `PARSER_MODEL_REQUEST_HARD_TIMEOUT_SECONDS`、`PARSER_GENERATION_TOTAL_TIMEOUT_SECONDS`、`PARSER_AGENT_MAX_TOOL_ROUNDS` | 外层候选预算、单请求超时和工具轮次是不同限制 |
| 数据库 | `POSTGRES_HOST/PORT/DB/USER/PASSWORD` | FastAPI、Worker 与 Django 指向预期数据库；Django 使用专属 schema |
| 队列 | `CELERY_BROKER_URL`、`CELERY_RESULT_BACKEND`、`CELERY_WORKER_ROLE`、`CELERY_WORKER_QUEUES` | Worker 必须消费任务所在队列，Windows 使用 solo；AI 任务需要 `netops.ai` |
| Redis | `REDIS_HOST/PORT/DB/PASSWORD` | 缓存、租约、进度与队列用途分别核对，不凭单个 ping 认定业务就绪 |
| 对象存储 | `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_SECURE`、`MINIO_BUCKET_NAME` | 浏览器上传地址与容器内部地址不同；详见网盘指南 |
| 网盘 | `STORAGE_MAX_FILE_BYTES`、`STORAGE_MAX_USER_BYTES` | 服务端限制与前端提示应一致 |
| 认证 | `JWT_SECRET_KEY`、`BFF_REQUIRE_AUTH`、`ENFORCE_BFF_ORIGIN` | BFF 与 FastAPI 一致，网络禁止绕过 BFF；具体角色由用户数据决定 |
| 附件 | `PUBLIC_APP_URL`、`ARTIFACT_DOWNLOAD_SECRET` | 外部下载链接应能从实际使用环境访问 |
| 日志与跟踪 | `LOG_LEVEL`、`LOG_FORMAT`、`LANGFUSE_HOST/PUBLIC_KEY/SECRET_KEY` | 未配置 Langfuse 不等于 SSE 不可用 |
| ITSM | `ITSM_WEBHOOK_SECRET`、`ITSM_CALLBACK_URL` | Webhook 认证与回调目的地分开配置 |
| Skill 目录 | `SKILL_CATALOG_*` | 目录启用、分层路由和语义检索是独立开关 |
| 巡检缺口 | `PRODUCTION_GAP_LEDGER_ENABLED` | 缺口提升为草稿不等于自动发布 |

模型字段具体回退规则见对应客户端实现，不假定所有 Provider 都支持同一采样参数。前端 `VITE_*` 是公开构建配置，不能放服务端密钥。

## 服务角色与旧配置

默认核心部署不要求 Qdrant。其连接诊断仍有代码入口，因此保留 `QDRANT_HOST/PORT`；未使用的 collection 设置已移除。当前 RAG 路径见[系统架构](01_系统架构设计.md)。

Streamlit UI 与 Supervisor v1 启动选项已退出，`STREAMLIT_SERVER_PORT` 和 `USE_SUPERVISOR_V2` 不再控制任何当前服务。旧 `.env` 中残留这些字段不会恢复旧 UI。

## 配置验证

先按[部署指南](10_部署安装手册.md)运行 Compose 配置解析，再按[运维指南](11_运维技术手册%20&%20故障排查.md)检查服务与业务路径。生产覆盖使用 `ports: !override`，必须确认当前 Compose 能解析且最终仅有预期绑定；不能只看覆盖文件中的一行地址。

安装、迁移、重启及测试命令见[开发与构建](06_环境%20&%20编译构建说明.md)。
