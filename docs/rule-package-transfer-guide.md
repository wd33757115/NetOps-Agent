# 规则包导入与导出

规则治理 1.3.0。在工作台打开规则治理 → 规则包导入导出；检查项目录和已发布资产也支持多选后进入导出。只需要规则治理 App 使用权。

## 导出

选择检查项、TextFSM、Change、状态/事件、采集实现、字段契约、比较/标识/评估策略版本。支持跨类型选择、选中项及依赖导出、全部已发布资产导出。选择草稿或停用版本时必须勾选允许未发布版本。

导出检查项自动收集关联实现、Parser、字段映射与规则依赖。当前状态规则和事件规则共用事件资产表。生效运行包引用的旧依赖保持精确版本，运行包装配关系作为 recipe 保存，不直接复制生效状态或历史运行记录。

可选携带已保存且摘要一致的脱敏 Parser 样本；没有可用样本时数量为零，不虚构验证证据。期望解析结果在本地限时子进程重新计算。样本仍可能保留业务信息，分享前检查包内容。设备账号、凭据、设备绑定、生成任务、巡检历史与来源审批不导出；目标环境的设备范围/评估绑定单独配置。

## 导入与发布

1. 上传 `.netops-rules.zip`，最大 12 MB。预检不写业务资产；核对文件、类型、依赖、TextFSM 字段契约、Change/事件结构，以及携带样本的回放结果。
2. 查看新增、复用、创建新版本数量及每项内容差异。同版本号内容不同会明确标识；必须勾选确认才创建新版本。不会覆盖正在生效的版本。
3. 确认导入，所有业务行与来源记录在一个事务内保存。版本发生并发变化时重新预检；失败回滚。同文件重试返回原导入记录，重新打包的相同内容复用已有资产。
4. 在结果或历史详情中检查本地发布条件。检查项/实现已创建目录治理草稿，可以打开原有发布界面；Parser 复核复用原有对比、样本回归、人工复核和发布接口。包内样本明确标为规则包来源，不伪造设备快照或源任务。
5. Change、事件等仍须满足原有规则发布门禁；按保存的运行包依赖关系完成本地验证及运行包装配。导入成功、来源回放通过都不等于已经生效。缺少本地样本时通过样本导入补齐。

有依赖缺失、无效规则或不支持格式时预检阻止导入并定位资产，不静默丢弃问题规则。现存历史规则若不符合当前 DSL，也会被识别；本功能不自动修改其语义。

## 文件与 API

ZIP 内包含 `manifest.json`、`assets/*.json`、`templates/*.textfsm`、`recipes.json`、`samples.json`。格式版本 `netops.rules/v1`，每个文件有 SHA256。该校验用于发现损坏，不代表来源可信或具有发布授权。

资产白名单仅交换业务字段。`$ref` 是包内引用，导入映射为本地 ID；检查项等业务标识保持稳定。Parser 携带字段契约和原文，审批、回归状态及源任务执行权不随文件复制。导入草稿的摘要按本地内容重新生成。

接口统一位于 `/api/apps/rule-governance/rule-packages`：

- `GET /assets`：按类型、状态、搜索分页选择资产。
- `POST /export`：所选引用/全部生效、是否带未发布版本和样本。
- `POST /preview`：base64 ZIP，返回差异、revision、样本及验证结果。
- `POST /import`：相同文件、revision、冲突确认；返回本地映射和目录草稿。
- `GET /history`、`GET /history/{id}`：记录与详情。
- `POST /history/{id}/validate`：读取当前目标状态并调用既有运行包装配规划器检查阻塞项。

ZIP 不落地解压，不接受服务器文件路径；拒绝目录穿越、链接、重复文件、未声明文件、未知字段、来源审批字段、循环/缺失引用；限制压缩大小、展开大小、文件与资产数量。模板编译及样本回放在 25 秒限时子进程中运行。没有新的数据库表、Workflow、模型调用或授权体系。
