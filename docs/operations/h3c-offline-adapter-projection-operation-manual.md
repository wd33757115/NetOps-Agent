# 离线样本制作与验证：H3C 示例

核对日期：2026-09-06。适用于当前巡检规则工作台；命令名仅作示例，实际检查项、范围和标准由管理员确认。

## 准备

- PostgreSQL、任务 Broker、结果存储、MinIO、AI Worker 和 Beat 可用，模型配置有效。Qdrant、Langfuse 不是本流程的必需条件。
- 操作者具有 `netops.configure` 权限；自动发布需管理员启动或明确授权。
- 准备包含完整命令和输出的设备文件，保留设备身份、采集周期和来源。同一命令尽量提供多设备、多周期样本，以及与检查目的相关的边界情况。
- 示例命令：`display interface brief` 对应接口运行状态；`display transceiver diagnosis interface` 对应光模块指标。不要凭命令相似度自动认定检查项关联。

## 从样本到运行包

1. 从工作台进入“巡检规则工作台”，选择“适配新设备”并导入样本。也可从离线巡检的“补齐检查能力”复用已有文件。
2. 在检查项目录定义要检查的含义、实体、标准字段、单位和判断方式。保存检查项版本后，标准语义随版本固定。
3. 在来源任务中确认设备范围及命令与检查项的关联。这两项业务定义由人工负责。
4. 确认关联后查看“自动制作”。任务在后台进行规则准备、解析验证、标准转换和适配；管理员授权且发布门禁通过后激活运行包。
5. 出现待处理原因时查看对应证据。可以“暂停并接管”，等待当前步骤结束，再编辑解析器或高级字段转换。继续后重新验证，不能把人工编辑直接视为已发布。

管理员自动发布授权只覆盖指定版本、命令和设备范围，且有有效期。模型生成成功与单个 Parser 已发布，都不等于整套检查能力已具备正式巡检资格。

## 校对顺序

命令详情中的比较区域按以下顺序纵向展示：

1. **CLI 原文**：核对命令、当前样本和边界信息是否完整。
2. **生成的 TextFSM**：对应当前候选的模板内容；多记录集场景应结合当前选择的记录集检查。
3. **实际解析结果**：核对行数、字段、空值及枚举，避免因缺少某类样本误认覆盖完整。
4. **标准检查结果**：核对实体身份、数值、单位和阈值，不能只检查字段名称相同。

例如光功率的“无模块”样本只能证明缺席状态，不能证明已经具备 RX/TX 功率及阈值解析能力。接口名称应与实际设备输出一致；不得把未知值默认为正常。完整执行证据和字段转换编辑器可按需展开。

## 发布后复检

发布完成后返回原离线巡检，选择“复用文件新建分析”，重新预检并执行。原报告保留，新任务使用重新确定的检查能力。历史文件不能因本次重新分析就被升级为网络现状证明。

验收同时核对覆盖情况、无法判断原因、异常命中和报告证据。正式运行包要求的兼容性或版本切换证据不满足时，按页面阻断原因处理；不要用修改状态或绕过审批接口代替。
