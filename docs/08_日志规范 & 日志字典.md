# 日志与排障上下文

核对日期：2026-09-06。实现见 [logging.py](../src/core/logging.py)。Langfuse 与 SSE 的关系见[观测指南](observability-guide.md)。

## 记录用途

应用日志用于排错，Langfuse 用于模型和步骤跟踪，数据库审计记录用于追溯操作。三者不能互相代替，也不能因为缺少 Langfuse Trace 就判定后台任务未执行。

FastAPI 与 Celery 初始化 structlog，并桥接 Python logging。`LOG_FORMAT=console` 适合本地，`json` 适合采集。输出包含时间、级别、事件、模块以及已绑定上下文。

## 编写日志

```python
from src.core.logging import bind_context, get_logger, reset_context

log = get_logger(__name__)
pairs = bind_context(run_id=run_id, user_id=user_id)
try:
    log.info("report_render_started", format=output_format)
finally:
    reset_context(pairs)
```

事件名使用稳定字符串作为第一个参数，避免重复传 `event=`。失败时记录业务标识、阶段和可公开诊断，不打印密钥、完整用户输入或未经脱敏的设备输出。

当前上下文字段：`request_id`、`trace_id`、`run_id`、`thread_id`、`user_id`、`ticket_id`、`celery_task_id`。`bind_context` 返回 token 列表，`reset_context` 恢复原值；不要在任务中清掉由 Worker 信号绑定的外层上下文。

## 排查入口

| 现象 | 首先定位 |
| --- | --- |
| HTTP 失败 | `request_id` 与 BFF / FastAPI 对应请求 |
| Workflow 停滞 | `run_id`、步骤状态、Worker 队列及租约 |
| 规则自动制作停滞 | 命令任务标识、Parser 子任务、AI Worker 与 Beat |
| 模型超时 | Provider 请求、调用预算及 Trace（若已配置） |
| 报告下载失败 | Manifest、对象键、摘要及对象存储响应 |

本地脚本日志通常写入 `.runtime/test/logs`，文件名取决于当前启动的角色；容器环境通过 Compose logs 获取。事件名以实际 `log.*` 调用为准，不维护另一份宣称完整的静态事件表。

日志只能提供线索。判断发布、审批、资产版本和历史报告内容，应读取对应数据库事实和不可变证据。查看[运维排障](11_运维技术手册%20&%20故障排查.md)与[维护验证](maintenance.md)。
