# 运维与故障排查

核对日期：2026-09-06。安装和进程启动见[部署指南](10_部署安装手册.md)，配置来源见[配置参考](07_系统配置说明.md)。

## 先确认执行环境

识别使用本地进程还是 Compose、核心服务还是 AI 服务、是否读取预期数据库。HTTP 存活只证明进程可应答；巡检就绪还需要设备范围、运行资产、队列和对象存储。

Windows 测试环境可执行 `scripts/test/verify.ps1`。通过 BFF 查询 `/api/health/` 与 `/api/health/diagnostics/`；受保护的诊断需使用相应登录身份。生产 FastAPI 不直接暴露到宿主机，不能为了健康检查临时打开公网端口。

## 按现象定位

| 现象 | 核对顺序 |
| --- | --- |
| 无法登录 / 401 | Django 可达 → 用户和分组 → JWT 配置 → 刷新 Token；不要通过反复 seed 重置用户 |
| 页面可见但操作 403 | 当前能力、所有权和范围；隐藏按钮不是服务端授权 |
| BFF 502 / 503 | FastAPI 进程 → BFF 上游地址 → 网络 → 超时和服务端日志 |
| 聊天无回复 | SSE 事件 → 路由 → Provider → Skill/Workflow 状态 → Worker |
| 后台任务排队 | 队列路由 → 消费该队列的 Worker → Broker → 调度与租约 |
| 自动制作停住 | 检查项与命令关联 → 样本/Parser 诊断 → AI Worker/Beat → 授权与发布门禁 |
| 巡检完成但无法判断 | 证据完整性、资产缺口、时间与基线、标准转换，不按完成状态推断健康 |
| 上传或下载失败 | 所有权 → 文件状态 → 实际浏览器可达地址 → 对象存在性和摘要 |
| Word / Excel 导出失败 | API details → 冻结报告资格 → 渲染依赖 → 对象存储 |

重试前确认原任务是否仍运行或已完成；进度界面暂时无更新不是重新发布的理由。重启不能替代修复数据和依赖门禁。

## 日志与追溯

本地启动日志位于 `.runtime/test/logs`；容器通过 Compose logs 查看。按 request_id、run_id、task_id 或制作任务标识关联进程，详见[日志指南](08_日志规范%20&%20日志字典.md)。Langfuse 未配置时仍可读取持久任务和 SSE 进度。

数据库巡检关注连接、锁、磁盘、长任务和失败状态；Redis 关注连接、内存、租约及队列；MinIO 关注容量、对象可读性和公网/内网地址。不要输出完整 `.env`、启动器密钥或未经脱敏样本到工单。

## 备份、恢复与升级

备份范围包括 PostgreSQL 业务数据与 Django schema、对象存储、必要的配置及索引。`scripts/prod/backup.ps1` / `backup.sh` 是辅助入口，执行前核对脚本中的数据库名、用户、桶和目标目录是否适合本环境。

恢复应在隔离环境验证用户、资产版本、Manifest 和附件摘要。只存在备份文件不证明可恢复。升级前保存当前镜像/代码、迁移状态及备份，按[上线检查](13_生产上线清单.md)验证新版本；不能通过清空 volume 解决迁移冲突。

旧任务和报告兼容路径在[退出登记](implementation/deprecations.yaml)中追踪。删除代码前需要实际数据与调用证据，不能因为到达计划日期就移除历史读取能力。
