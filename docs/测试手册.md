# 测试与回归手册

核对日期：2026-09-06。测试范围跟随变更和业务风险选择；以下命令从项目根目录执行。

## 环境边界

纯单元测试尽量使用临时文件和隔离存储。部分 `tests/unit` 仍直接访问数据库，不能把该目录名当作无副作用保证。全量测试、集成回放、部署冒烟和性能脚本必须使用独立数据库、队列与对象存储；ITSM 回调使用测试接收端。

依赖角色和安装方式见[开发指南](06_环境%20&%20编译构建说明.md)。使用仓库虚拟环境，不依赖某位开发者的绝对目录。旧一次性设备数量和样例耗时不作为当前验收标准。

上表文件位于 `tests/unit`。运行前查看测试 fixture 和依赖；测试名不能代替阅读。自动发布集成测试使用隔离数据库与样本，不发布目标环境资产。

```powershell
venv\Scripts\python.exe -m pytest tests/unit/test_command_adapter_v2.py tests/unit/test_canonical_rule_context.py -q
```

前端 Vitest 覆盖组件行为；Playwright `test:e2e` 与 `test:visual` 覆盖浏览器流程和视觉回归。构建、lint 与 Mock 测试不代替实际浏览器，也不代替真实设备或模型质量验证。

## 完成证据

记录代码版本、执行命令、测试环境、退出码及失败详情。测试失败先区分环境缺失、陈旧断言与行为回归，不能只删测试让检查变绿。测试命令只证明覆盖的行为，不宣称整个系统上线。

目标环境检查、黄金样本回放和生产就绪脚本见[scripts/test](../scripts/test/)。脚本如会生成任务、资产、报告或回调，先在隔离环境执行。项目清理回归记录见[维护与验证](maintenance.md)。
