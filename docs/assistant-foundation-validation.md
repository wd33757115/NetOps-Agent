# Assistant 诊断基础与评测记录

日期：2026-09-21。交付版本：Assistant 0.4.0、Inspection 1.1.0。
本记录说明当前实现与实测边界；P6 的完整业务验收尚未完成。

## 架构与业务证据

DSH 继续独占 Agent 执行循环，原生 glob/grep/read 按需阅读资料，官方 MCP 客户端调用已有业务契约。
不新增 Workflow、Agent 执行器、向量服务、队列或任务表。现有 App 清单与生命周期完成注册、构建、升级和授权。

Inspection 新增五项只读契约，HTTP 与 Agent 复用同一函数：

| 工具 | 输出与边界 |
|---|---|
| search_devices | 资产标识、型号、版本、站点和登记/连接检查时间；不返回凭据或任意扩展属性 |
| list_runs | 采集、解析、事实、分析阶段及运行用途；不把历史/离线记录当作实时健康 |
| list_events | 设备、运行、事件、严重度及首次/最近出现时间；空结果不等于没有故障 |
| list_snapshots | 原始命令快照索引、采集时间、解析质量及摘要，不直接携带全文 |
| read_snapshot | 按快照 ID 分页读取先脱敏的原文，最多4000字符，保留采集时间和下一页位置 |

API 为 POST `/api/apps/inspection/diagnosis/{工具名}`。列表每页默认10条、最多20条；
运行/事件/快照支持设备、运行ID及带时区的时间范围。工具不触发设备采集或网络变更，不读取 Workflow。
助手仅暴露显式声明 `evidence=True` 的只读契约；旧的无界结果查询不再直接送入模型。

每次业务读取生成 evidence ID、来源 App、读取时间和内容摘要，快照沿用现有消息引用存储。
单项证据最多24000 UTF-8字节，超限要求缩小查询，不能截断 JSON 后冒充完整结果。
执行前、最终发布及打开引用都验证源 App 使用权；历史列表不携带业务原文。
资料引用仍限定本轮实际读取的行与修订；目录、搜索预览、未读取行及虚构业务 ID 都不能作为最终来源。
脱敏是已知凭据模式的防护，不宣称能识别任意厂商配置中的全部秘密；新增命令格式应扩充对应规则和测试。

## 用户可见过程与运行数据

主聊天与 Assistant App 展示同一执行摘要：准备、搜索/阅读、业务调用、综合、完成/失败及停止。
历史记录保留步骤和耗时，刷新可恢复；只记录实际回调，不生成虚假的“思考过程”，不存内部推理文本。
原文/业务证据可在抽屉回查。Markdown 支持命令、列表和表格，禁用原始 HTML 与远程图片自动加载。

每轮记录模型轮数、工具次数、输入字符累计、总耗时和模型实际返回的 token 用量。
未返回用量时为 null；不根据字符数伪造 token 或费用。失败区分提供方超时、不可用、整轮超时和引用校验失败。
日志只记录运行编号、终态和统计，不记录提示全文、模型推理或业务原文。
90秒外层截止时间仍为最终约束；SDK等待时限与其对齐，取消/退出撤销凭证并回收进程树。

## 冻结质量基线

数据为用户提供的**一份**华为云 Stack 8.2.1 手册中的五个选定片段，加六份合成控制资料。

不是30份独立业务场景，也不是原计划要求的5–10份独立手册。

模型 deepseek-v4-flash，DSH SDK/runtime 0.1.5rc1，Windows Python3.13，每题1次，最多两题并发。
先完成开发集调整，再冻结配置运行完整集；保留题未用于本轮提示调优。

Linux Python3.13 容器内14项测试通过：真实 SDK 原生文件工具、MCP、只读数据库契约、取消、超时以及 `/proc` 确认无遗留SDK子进程。
源码只读挂载，模型为本地替身；不是目标生产服务器或真实网络设备验收。
Windows 定向回归76项通过、1项仅Linux的进程检查跳过；包含助手、引用授权、评测、内核及巡检兼容读取。
初跑的一处旧测试夹具未声明新的 evidence 契约，修正后阅读模块7项全部通过，以上为去重结果。
前端47文件215项测试通过；轮询依赖修正后Assistant页面3项复测通过。定向Ruff/ESLint和生产构建通过。
已有第三方WebSocket弃用提示和React Router未来版本提示不影响上述结果。

正常本地环境执行启动脚本升级并启用 Assistant0.4.0、Inspection1.1.0，保留其他三项业务App和原授权。
Gateway、Django BFF、React生产预览、Celery Worker/Beat以及全部5个启用App部署一致性验证通过。

真实BFF/SSE只读业务问答：查询专用的不存在资产名称，返回空结果，回答明确不能证明实时健康；
1项官方MCP查询、1条业务证据，首次过程1.129秒、最终答案52.596秒，8次过程快照。
历史过程与SSE完全一致，公开历史未携带业务原文，点击引用能读取授权快照；参数越界/任意路径字段返回422。
后续3次相同HTTP只读查询分别1.299/1.178/1.292秒。此单题全链路时延高于隔离评测，
后续应分解授权、工具、模型及持久化耗时；不能用隔离评测P95代替在线P95。
本次查询未扩大设备范围，未触发设备采集、巡检或网络变更。

`assistant-linux-tests.log` 和 `assistant-foundation-live.json`。

## 采用的实践依据

- [DSH官方SDK](https://github.com/deepseek-ai/deepseek-harness/blob/master/python/sdk/README.md)：复用SDK的子进程、会话和执行循环；平台维护生命周期与业务边界。
- [MCP工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)：声明只读工具提示，服务端仍独立执行授权与参数校验，不能把提示当安全边界。
- [Anthropic Agent评测实践](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)：分开任务、执行轨迹和结果，保留失败，结合确定性检查与领域审阅。
- [Google SRE监控](https://sre.google/sre-book/monitoring-distributed-systems/)：以延迟、失败及可定位的运行记录支持运维，而非只记录模型“回答成功”。
- [react-markdown安全说明](https://github.com/remarkjs/react-markdown#security)：使用安全文本渲染，不开启原始HTML解析。
