# 系统管理操作说明

系统管理由 admin 与 netops-config 按权限使用。工作台顶部和左下角账号菜单均提供入口：admin 进入用户管理，netops-config 进入应用授权。旧 `/users` 保持管理员跳转。

## 用户

搜索账号或邮箱，创建用户、编辑邮箱与平台角色、启停账号、重置密码或删除用户。密码沿用现有复杂度校验。当前登录账号不能删除或停用，内置 admin 账号不能删除，必须保留启用的管理员。

默认系统组只有两个：`admin` 拥有全部系统管理权限和所有已启用应用的使用权；`netops-config` 可以为用户和用户组授予、撤销应用使用权，不能创建或删除账号、管理用户组或提升管理员身份。普通用户无需加入角色组，获得某个 App 使用权后可以使用其全部业务功能。

## 用户组

在 `/system/groups` 创建业务组。编辑器直接显示已加入成员，可按用户名或邮箱搜索、分页浏览、逐项或批量移出；点击“添加用户”进入候选列表，支持服务端搜索、分页和跨页选择。修改后点击底部“保存用户组”。账号停用不会自动删除组关系，列表标明停用状态。

`admin`、`netops-config` 不可删除或改名，但 admin 可以管理两组成员。加入 admin 获得全部系统权限，移出时同时移除管理员标志；至少保留一名启用的管理员。自建业务组支持删除。用户页面也可维护管理员角色及 netops-config 成员身份。

删除组前会显示成员数和应用授权数量。删除只解除组关系和该组的 App 授权，保留账号、直接授权和其他组授权。

## 应用授权

在 `/system/apps` 搜索应用，点击“管理授权”，分别添加直接授权用户或授权用户组。已授权对象在分页表格中展示，可逐项或批量撤销；“撤销全部显式授权”清空用户及组授权草稿，仍需保存才生效。界面会按当前编辑内容预览每个人的权限来源和可用状态，点击“保存授权”后提交。

- 直接授权和组授权取并集。移除其中一项不代表所有来源都已撤销，应核对“权限来源预览”。
- 管理员默认权限不通过这里撤销；如需调整平台管理员身份，使用用户页面。
- 账号停用或应用未启用时，即使保留授权也不能使用。启用应用仍走现有能力包发布流程。
- 保存失败会保留编辑内容。如提示授权或用户组已变化，请关闭编辑器、刷新并重新核对，避免覆盖其他管理员的更新。

## 实现与兼容

复用 Django User、Group 和 AppGrant，无新增数据库表。用户组维护 API 为 `/api/platform/groups/`，授权沿用 `/api/platform/apps/admin/`。账号与用户组写接口只允许 admin；应用授权和分页对象查询允许 admin、netops-config；业务接口继续实时检查当前用户及其组的 App 授权。

用户组与授权变更写入现有认证审计，记录修改前后内容，不记录密码。新的授权页面携带版本摘要检测并发冲突；旧授权 API 调用保持兼容。

## 2026-09-23 迁移说明

数据迁移 `0005_system_groups` 创建或保留两个默认组，将已有超级管理员同步到 admin。旧 operator、viewer 组的 App 授权转为原成员的直接授权后删除旧组，自建组、账号和已有直接授权保持不变。普通账号不再自动创建或加入 operator/viewer 默认组。

netops-config 的权限现为 `apps.manage`，它本身不再授予旧 `netops.configure` 系统配置权限；已有明确 App 授权仍按原记录生效。移出 netops-config 后，后端立即拒绝其授权管理请求，旧登录 token 不能恢复该权限。
