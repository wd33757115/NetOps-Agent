# 生产上线检查

核对日期：2026-09-06。此表是目标环境执行清单，不表示本仓库已经在生产通过验收。

## 部署与数据

- [ ] 使用已验证代码/镜像及依赖锁定文件，前端与 API 同版本。
- [ ] 按[部署指南](10_部署安装手册.md)解析全部 Compose 覆盖，确认 FastAPI 不映射宿主机端口，中间件仅有预期绑定。
- [ ] 根据业务选择核心与 AI 服务，Worker 消费正确队列，Beat 和任务恢复机制正常。
- [ ] 按[数据库说明](03_数据库设计%20&%20数据字典.md)完成 FastAPI/Alembic 与 Django 迁移，保留迁移结果。
- [ ] 备份 PostgreSQL、Django schema、对象存储和必要配置，在隔离环境验证恢复。
- [ ] 正式环境无开发热重载；需要 HTTPS 时配置实际入口代理、证书和 SSE 转发。

## 配置与用户

- [ ] 替换安装示例密钥与口令，Django/FastAPI 的认证配置一致。
- [ ] 登录、角色和 `netops.configure` 权限符合用户职责，非管理员不能自行授权发布。
- [ ] 不在既有正式用户库反复运行 `seed_auth_users`；该命令会重置演示账号密码和分组。
- [ ] 前端只使用公开的 `VITE_*` 构建配置；模型及存储密钥留在服务端。
- [ ] 上传、预览、下载和回调地址从实际用户环境可达，避免 localhost/容器域名泄漏为外部链接。

## 业务验证

- [ ] 不同角色登录后，菜单、直接路由和 API 权限一致。
- [ ] 网络巡检在线和离线两条路径均覆盖成功、缺口和失败场景，历史报告不会变成当前健康结论。
- [ ] 规则自动制作覆盖人工关联、暂停接管、修复、授权及验证后发布，发布日志保留实际授权身份。
- [ ] 使用目标设备脱敏样本验证 Parser 和标准转换，不能只以 Mock 测试代替设备质量验收。
- [ ] 公文全文生成、文种切换、排版、版本保存与 Word 导出可用。
- [ ] 文件和报告下载满足所有权、用途和摘要要求。
- [ ] 启用的聊天、Workflow、ITSM 集成分别验证；回调测试使用隔离接收端。

## 运行与回滚

- [ ] 日志可按 request_id/run_id/task_id 追溯，故障告警和队列监控有效。
- [ ] 单元、契约、浏览器和目标环境回归按实际变更覆盖，记录命令与结果。
- [ ] 保存旧镜像/代码与配置，明确数据库迁移是否可逆；涉及数据格式变化时验证恢复策略。
- [ ] 保留已发布历史资产、任务和证据的读取能力，不凭清理计划删除生产数据。

脚本入口见[scripts](../scripts/README.md)，回归命令见[维护与验证](maintenance.md)。健康检查、构建成功或绿色单元测试都不能单独证明上线完成。
