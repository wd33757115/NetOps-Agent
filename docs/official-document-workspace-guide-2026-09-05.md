# 公文工作台使用与部署说明

日期：2026-09-05。状态：active。

## 入口与使用

从工作台打开“公文写作”，或访问 `/apps/official-documents`。列表支持搜索、文种及状态筛选、分页和回收站。新建时可填写需求生成初稿，也可直接进入空白稿编辑。

编辑页采用已确认的“左侧纸张、右侧助手”布局。左上角选择文章种类（通知、函件、请示等），正文支持加粗、下划线、换行、撤销重做及缩放。段落角色由生成结果确定，不再作为主要工具栏选项。手机通过“文档 / 助手”切换，工具栏保留保存、历史和导出入口。

修改后自动保存。保存过程中继续输入会排队提交；离开前提示保存。本地未同步稿按账号和文档隔离保留。遇到其他页面修改引起的版本冲突，可另存本地稿或明确加载服务器最新版本。

“生成全文”默认生成或更新完整公文，光标位置或选区不会将其缩小为局部任务。全文生成复用原公文 Skill 的 `OfficialDocumentJSON`：标题、主送、导语、每节标题和正文、结尾、署名、日期分别转换为段落；缺失整体结构的结果不会被当成完整公文。核对后点击“应用整篇公文”保存版本。

默认允许先起草：已知写作主题时先给出完整初稿，缺失姓名、单位、经历等使用待确认标记，不反复索取无必要的个人资料。可取消勾选“允许先起草，保留待确认信息”，改为补齐事实后再写。追问后的简短回复沿用最初写作需求。

当前文种是默认建议，明确的写作需求优先。比如选中“报告”时请求入党申请书，可以生成申请书候选，应用全文后才同步更新文章种类。新增“申请书”“入党申请书”模板，支持自然分段，不强制报告式小标题；未知文种沿用基础公文排版，不自动套用通知结构。`headings_required: false` 可配置无需小标题的文种。

只有明确选中文字，再使用“精简段落”或“更多 → 仅修改选中文字所在段落”时，才进行局部修改。单纯光标定位不算选区。助手还可追问缺失事实、回答问题和审查全文。文档发生变化后，旧建议不能覆盖新稿。

## 文种模板扩展

统一配置位于 `src/skills/official-document-writing/assets/workspace-templates.json`。编辑器、新建页和列表筛选均通过鉴权的 `GET /api/official-documents/templates/` 读取配置。新增文种只需追加一条配置，刷新页面即可读取，无需修改前端下拉框：

```json
{
  "id": "meeting-invitation",
  "doc_type": "会议邀请",
  "name": "会议邀请",
  "aliases": ["年会邀请"],
  "sections": ["会议安排", "参加要求"],
  "closing": "敬请出席。",
  "recipient_required": true
}
```

`doc_type` 应保持唯一、稳定；`name` 为菜单名称，`aliases` 用于兼容历史名称。`sections`、`closing` 提供生成指导，不能替代用户事实。可选 `format` 覆盖排版属性；未指定时继承公文 Skill 的公共格式。模板配置在任务提交时冻结，避免任务执行期间配置变化影响结果。

网页和 DOCX 共用 `src/core/official_documents/templates.py` 的格式定义：A4、上 37 / 右 26 / 下 35 / 左 28 mm，标题小标宋 22 pt，正文仿宋 16 pt，行距 28 pt，首行缩进两字，一、二级标题分别黑体、楷体。网页随缩放换算为像素，窄屏压缩纸张留白便于编辑。浏览器使用本机字体，缺少小标宋时使用宋体系列后备字体；Word 记录指定字体，实际显示同样取决于终端字体。

切换文种会保存新的文种信息并应用对应格式，保留已有正文。需要按新文种重新组织内容时，点击“生成全文”。目前是配置文件扩展，不包含上传任意 DOCX 模板的管理界面。

待确认信息在助手侧逐项展示，补入正文后可标记已核实。定稿会检查标题、正文、发文机关、有效成文日期和待确认标记；通知、请示、函、报告还检查主送机关。这些是基础完整性校验，不能替代正式内容审核。

历史恢复会创建新版本。定稿后需“重新编辑”才能修改。导出只有“导出 Word”一个入口：先保存当前修改，再下载完整文档。未补齐的信息照原文保留，不阻止导出，也不额外添加草稿页眉；定稿校验独立保留。

Word 导出固定到提交时的版本，按钮在生成期间显示加载状态，完成后自动下载。页面不显示“Word 已生成”顶部通知栏；助手记录保留历史版本下载，刷新不会自动重复下载历史文件。失败时可重试当前版本的导出，下载失败可重试下载已有文件。兼容旧客户端的导出参数，但新请求统一生成普通 Word 文件。

## 后端与持久化

- `src/core/official_documents/`：内容合同、版本管理、局部修改校验、异步任务及 Word 渲染。
- `src/gateway/official_documents_api.py`：公文专用 API，前缀 `/api/v1/official-documents`。
- Django BFF：`/api/official-documents/`，沿用登录认证和可信身份转发。
- `official_documents`、`official_document_versions`、`official_document_operations`：文档、不可变快照及持久任务。
- 每篇公文关联专用会话，隔离于普通聊天列表。模型任务冻结文档、用户要求、最近上下文与参考时间。
- Celery `netops.ai` 执行任务，beat 每 30 秒补投排队或租约过期任务。任务取消、删除及失效 worker 的迟到结果不会更新文档；连续中断达到上限会进入失败状态。
- MinIO 按用户、文档、版本、内容摘要保存 DOCX，通过鉴权下载接口返回，不将内部对象键返回前端。

页面仅在任务运行期间轮询状态，刷新可恢复。另提供任务事件 SSE 接口，每次轮询使用短数据库事务。

## 部署与回退

后端安装现有 gateway、Django、AI worker 依赖组合；AI worker 的 `requirements-ai-worker.txt` 已包含文档依赖。新增前端依赖为 Tiptap 3.31.3 的 core、react、pm、starter-kit，版本固定。

```sh
python -m alembic upgrade head
cd web/react_frontend
npm install
npm run build
```

随后重启 FastAPI、Django BFF、AI worker 和 Celery beat。需要 PostgreSQL、Redis、MinIO 和有效模型配置。公文模型沿用 `LLM_MODEL` / `LLM_PROVIDER`、`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`，结构化调用关闭 DeepSeek thinking 模式，以兼容当前提供方的工具调用限制。旧聊天公文 Skill 保留；审核异常现在明确返回失败。

`VITE_OFFICIAL_DOCUMENTS_ENABLED=false` 重新构建可隐藏新入口；`OFFICIAL_DOCUMENTS_ENABLED=false` 重启后关闭新增 API。回退保留数据表和版本，不执行删表迁移。

本地已应用 `0100_official_documents`，目标为 `localhost:5432/netops_agent` 的 `public` schema；三张表与 ORM 比对无差异。该迁移与桌面布局的 Django 迁移独立。
