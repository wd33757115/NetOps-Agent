# 规则资产包导入与导出实施计划

日期：2026-09-23。状态：已实施，规则治理 1.3.0 已在本地启用。

## 目标与边界

在规则治理 App 中迁移检查项、采集实现、TextFSM、字段契约、状态/Change/事件规则及必要依赖。复用既有资产表、验证与发布服务，不引入 Workflow、模型调用或包内权限角色。导入产生待验证版本，不覆盖生效版本，不改变冻结巡检。

## 实施顺序

1. 定义 v1 ZIP/JSON 交换格式、文件校验、明确的资产白名单与依赖闭包。支持按检查项、单项/批量资产、全部生效资产导出；草稿和样本显式选择。
2. 实现只读预检、资产内容差异、版本冲突、目标快照校验、包内引用到本地 ID 映射。新增版本与复用在一个事务提交；重复导入幂等。历史验证不作为本地发布依据。
3. 实现规则包工作区和目录/资产列表快捷入口，上传、预览、确认、验证结果与历史记录；接入既有发布入口。
4. 测试独立数据库往返、Parser 样本一致性、依赖完整性、重复导入、冲突、失败回滚、恶意/损坏压缩包及 App 权限。完成前端测试、构建、实际页面验证与部署核对。

## 格式与冲突规则

文件扩展名 `.netops-rules.zip`；manifest 标注 schema 版本、所选根资产、内容 SHA256；资产 JSON 与 TextFSM 原文分别存储。引用只允许白名单内资产。包不包含设备凭据、设备绑定、巡检历史、任务执行权或源环境审批权限。

相同业务身份/版本/内容复用；同身份不同内容明确展示差异并经确认创建本地新版本；相同版本号不同内容显式标识冲突。缺失依赖、未知格式、无效类型阻止写入。预检后目标数据变化要求重新预检。

## 界面设计

视觉：沿用规则工作区的白色宽屏表格与蓝色操作，紧凑清晰。内容：资产选择和导出、文件预检、逐项差异、导入结果和历史。交互：步骤切换、详情抽屉过渡、按钮处理中反馈；遵循减少动态效果设置。

## 验收

- 检查项及其 Parser/映射/Change/事件可跨环境往返，内容与引用保持一致。
- 同一样本在导出前和导入后得到一致的解析结果，规则语义不变。
- 预检不改变业务资产；失败无半套资产；重复导入不重复生成版本。
- 已发布版本和历史冻结引用不受影响；本地验证与发布不能被包内报告绕过。
- 有规则 App 使用权限即可操作，无权限 API 拒绝；手机页面无全页横向溢出。

## 实施结果

- 已完成 v1 格式、18 类资产与依赖引用、受限 ZIP 读取、选中/全部生效导出、只读预检、差异及冲突确认、事务导入和审计历史。
- 导入创建草稿，检查项/实现进入原目录治理；Parser 样本接入原复核入口。运行包装配关系留存并可检查本地发布条件，不自动发布。
- 后端 56 项测试通过，覆盖独立数据库往返、依赖映射、冲突、幂等、回滚、非法 ZIP、权限和事件 DSL 兼容性；前端 22 项测试通过，生产构建通过。
- 实际浏览器完成检查项导出、上传预检、差异查看、原样复用导入、发布条件检查和历史查看。该次导入复用 18 项资产，未改变生效版本；桌面/移动端检查通过，未发现页面脚本错误或 axe 可访问性违规。
- 已同步事件校验器与现有执行器支持的显式状态值字段。真实 API 对 6 条此类事件及其 109 项依赖完成导出和预检，全部复用。
- 本地版本经过停用、空闲服务维护和启用核对。此次维护前业务待处理任务为零，没有为发布取消业务任务。

## 已知数据问题与边界

现存 52 条生效事件版本中有 2 条使用执行器尚不支持的 `linear_power_baseline_loss`：`interface.optical_power.OpticalRxPowerDegraded` 和 `interface.optical_power.OpticalTxPowerDegraded`。包含这两条的包会被导入预检阻止；应先在原规则治理中修正规则及验证语义，再重新导出。本次没有自动替换条件或改动现有规则数据。

本次交付的是规则资产迁移能力。源环境审批、设备绑定及巡检历史不迁移；目标环境仍按既有流程完成验证与发布。使用说明见 [规则包导入与导出](rule-package-transfer-guide.md)。
