# 网络巡检与规则工作区操作说明

核对日期：2026-09-22。巡检 1.2.0 的侧栏、摘要和响应式布局见[工作台指南](workbench-apps-guide-2026-09-05.md)。

后续自动化改造见 [自动制作与授权发布](./patrol-rule-autopilot-guide-2026-09-05.md)：人工确认关联后增加后台检查点调度；管理员授权的任务可在验证通过后自动发布。下文原制作阶段与手工操作仍保留为人工接管入口。

## 1. 用户现在如何完成工作

### 网络巡检

1. 从工作台打开网络巡检，默认显示“全部任务”，汇集在线和离线各最近 20 项；需要更早记录时进入各自历史页，保留服务器分页。
2. 点击“新建巡检”，选择在线采集或离线文件。离线支持单周期和双周期；在线仍执行范围预览、环境检查和发起门禁。
3. 在线使用设备已绑定的巡检命令集。配置人员在设备管理中维护整套有序命令并绑定设备范围，检查项不决定采集命令。这里修改的是设备绑定，会影响后续执行，并非本次任务临时覆盖；普通用户使用已配置命令集。历史检查项型 Profile 暂保留兼容，不自动转换。
4. 已完成离线任务直接进入结果。任务名称、原始采集周期、历史分析/现状证明用途持续显示；报告下载和补齐能力入口位于结果上方。
5. 未覆盖或不具备结论资格时明确提示不能形成完整结论。零条风险不再自动被展示为健康；验证任务始终显示“规则验证”，下载名称为验证报告和验证明细。
6. “复用文件新建分析”复制文件引用与原始周期到新的历史分析任务，原任务和报告不被重置。新任务重新预检、确认后再执行，不沿用原现状证明或自动发布事件。

运行环境正常时折叠技术明细，有阻断时展开。移动端全部任务使用可以直接操作的纵向列表。原在线批次中的失败、跳过、规则证据、完整历史分页继续保留。

### 巡检规则工作台

入口名称从“巡检规则生成”改为“巡检规则工作台”。默认显示制作任务，以已有持久化检查项生产分组和命令单元为依据，展示阶段、待处理原因、样本和继续动作；没有另建一套任务状态机。

- “适配新设备”：进入样本导入，制作命令适配能力。
- “修改检查标准”：进入检查项目录，调整检查项及判断定义。
- 每个来源任务拥有“制作与验证”页，可继续具体命令；导入完成后能够直接进入该页。
- 具体命令通过任务 ID、命令、单元 ID 恢复定位，沿用已有 Parser、Projection、适配器审批阶段及服务端结果。
- 校对界面自上而下展示 CLI 原文、生成的 TextFSM、实际解析表和标准检查结果表；完整执行 JSON 和高级字段转换编辑器可展开。TextFSM 与当前候选比较结果一同读取，避免展示其他版本的模板。
- 目录的平台回放/切换工具收至管理员工具，高级 JSON 默认收起；检查项归类表收起为可选浏览，命令队列保持可见。
- 已发布资产、覆盖与回填、审计记录保持独立入口；旧链接继续经过兼容映射，并支持将冲突参数修正为推荐视图。

阶段恢复使用已有服务端任务。尚未提交的自由编辑文本并未新增跨设备自动保存，不把 URL 定位等同于完整编辑器草稿持久化。

### 设备管理审查与调整（2026-09-06）

入口为 `/apps/rule-governance/devices`，网络巡检工具栏和工作台均提供“设备管理”；使用 rule-governance App 使用权。

- 把藏在“更多”里的绑定操作提升为“绑定巡检命令集”。步骤为：勾选设备或选择分组 → 选择/新建整套命令 → 预览范围与解析缺口 → 确认绑定。
- 原来混用检查项选择、历史 Profile 字段与命令预览，容易让人误以为选一项就等于配置整套巡检。已替换为独立命令集窗口，移除设备表单里依赖历史字段的错误预览和重复查询。
- 设备资产首屏移除控制面统计和实现说明，保留常用筛选，其他筛选可展开。设备列表改为服务器分页，保留跨页勾选；修改筛选会清除旧选择并回到第一页。
- 新增/编辑设备保留资产与连接字段，扩展属性收进高级设置；保存后再配置命令集，实际生效命令以巡检预览为准。
- 原完整资产列仍支持横向滚动。平台模块与高级运维工具本轮继续保留；后续可依据日常使用频率进一步拆分，避免一次性改动所有管理功能。

没有自动创建真实设备、发起在线采集或覆盖现有绑定。本轮不涉及数据库结构迁移。

验证：巡检采集、原文导入、检查结果与绑定后端回归 104 项通过，命令集 API 回归 10 项通过；前端全量 171 项通过，随后新增的预览竞态测试及同文件其余 3 项通过；UTF-8、ESLint、生产构建通过。管理员实页已检查设备列表、设备表单和命令集窗口，当前数据库无受管设备，因此未进行真实设备采集。FastAPI 与空闲 Core Worker 已重新加载。日志位于 `.runtime/test/command-binding-*.log`。

## 2. 两个应用之间的衔接

离线结果的“补齐检查能力”携带原巡检 ID 和返回位置。用户先看到原文件数量及采集周期，点击后创建或继续制作任务，复用服务器已有文件引用，无需重新上传。

同一操作者从同一巡检补齐规则时使用固定幂等键；失败后重试读取已关联文件，只补充缺少的引用。创建来源任务不会自动调用模型、采集设备或发布规则。原设备身份线索供重新确认，不复制现状证明资格。

返回位置贯穿目录、来源任务、命令编辑及覆盖页。发布后可以回到原巡检，使用“复用文件新建分析”再验证。在线缺口继续使用已有的缺口与证据定位能力；本轮新增的原文件自动复用针对离线任务。

新旧分析目前是两个独立任务，尚无专门的分析版本关系表或并排差异页面；可分别查看两份报告。原报告不会因进入规则工作台或新建复检而被替换。

## 3. 代码清理

`ParserControlTab.tsx` 由约 2958 行旧控制器缩减为产品路由层。移除不再挂载的旧查询控制器、重复资产工作区和专用编辑表单：

- `DeviceSelectorForm.tsx`、`EffectiveDeviceForm.tsx`、`EventRuleConditionForm.tsx`
- `ParserDetailDrawers.tsx`、`ParserGovernancePanel.tsx`、`ParserWorkQueueWorkspace.tsx`
- `RuleAssetChainWorkspace.tsx`、`RuleAssetVersionWorkspaces.tsx`、`RuntimeAssetsWorkspace.tsx`
- `useParserControlData.ts`

同时删除只测试这些旧实现的 7 个测试文件，共 17 个文件。删除前后均按模块名核查引用；当前源码不再引用这些模块。保留并更新产品行为测试，覆盖旧入口、资产定位、权限门禁、失败证据和历史分页。

这些文件位于 `web/react_frontend/src/components/skills/parser/`。历史审查文档仍可能引用当时存在的源码，作为审查证据保留。没有根据名称猜测并批量删除后端文件、历史资产、报告、数据库表或迁移脚本。

## 4. 验证与部署

验证结果：UTF-8 检查、ESLint、Vite 生产构建通过；32 个测试文件、164 项单元测试通过；桌面和移动端共 24 个浏览器场景通过（22 项主回归与 2 项复检回归）。文档审计无失效链接或状态错误。日志保存在 `.runtime/test/patrol-refactor-check.log`、`patrol-refactor-e2e.log` 和 `patrol-reanalysis-e2e.log`。其中最终两项复检测试调整为匹配“继续离线巡检任务”标题后单独复跑通过。重点包括：

- 统一来源选择，正式执行前门禁仍有效。
- 历史结果进入规则样本复用，幂等创建、文件去重、返回原任务。
- 验证用途及覆盖不足不出现健康空态。
- 旧 Parser 链接、冲突参数、运行包阻断、证据追踪、批次分页和可访问性。
- 新建历史复检不调用原任务 retry/execute；保留采集时间和文件，失败可重试。

浏览器还只读检查了本机已有的历史巡检和规则来源任务，确认结果页、来源信息及制作队列可打开。自动化写操作使用 API fixtures；没有对实际设备发起巡检，也没有自动生成或发布生产规则。

第一阶段流程重构不涉及数据库结构或后端接口修改。后续权限补充涉及前后端鉴权，详见第 6 节，仍无需数据库迁移。实际设备采集、模型生成质量、跨厂商一致性及现场操作耗时需要在真实业务数据上持续验收；本说明不宣称已完成生产全链路验证。

## 5. 后续扩展边界

本轮落地主要流程和可证实的清理。审查中的规模与协作方向仍包括：本次任务独立方案覆盖、正反例回归库、统一发布影响摘要、分析版本关联与差异对照、编辑草稿持久化，以及大规模任务的跨来源分页。这些需要明确新的数据合同和后端行为，不以隐藏按钮或更名代替。

## 6. 设备与规则权限

设备配置和规则制作使用 rule-governance App 使用权，网络巡检使用 inspection App 使用权。管理员按用户/用户组授权，不再沿用旧 netops.configure 角色表说明。已有业务验证及对象归属边界保留，详见[权限指南](permissions-guide.md)。
