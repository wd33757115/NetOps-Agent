# 数据库与数据合同

核对日期：2026-09-06。表与字段的权威定义是 [SQLAlchemy 模型](../src/infrastructure/db/models.py)、[Alembic 迁移](../migrations/)和 [Django 模型](../web/django_backend/bff/models.py)。本文解释数据职责及维护约束，不再复制一份容易过期的完整 DDL。

## 存储分工

| 存储 | 数据 | 管理方式 |
| --- | --- | --- |
| PostgreSQL 业务 schema | 设备、巡检、检查项、规则、工作流、公文、报告与审计 | SQLAlchemy + Alembic |
| PostgreSQL `django` schema | Django 用户、分组、认证相关表和个人桌面布局 | Django migrations；默认 search_path 为 `django,public` |
| PostgreSQL checkpoint 表 | LangGraph 执行检查点 | PostgresSaver 初始化流程 |
| MinIO | 原始证据、上传文件、报告和 Word 等对象 | 数据库保存引用、归属与摘要 |
| Redis / Broker | 会话吊销、缓存、任务投递与结果等 | 以实际服务配置为准，不作为业务记录唯一来源 |
| Chroma / 可选 Qdrant | 知识检索向量 | RAG 组件管理，可重建索引不等于可恢复原始文件 |

Django 只有在显式设置 `DJANGO_DATABASE_ENGINE=sqlite` 时使用 SQLite。历史 `patrol.db`、Parser 验证文件和 Django SQLite 迁移工具仍有升级用途，不能据旧文件存在认定它们是当前业务数据源。

## 主要数据域

| 数据域 | 代表表 | 关系与用途 |
| --- | --- | --- |
| 设备 | `netops_devices`、`netops_device_groups` | 设备身份、范围、分组和连接健康；凭据通过专用仓库管理 |
| 巡检 | `netops_patrol_batches`、`netops_patrol_batch_devices`、`netops_patrol_runs` | 批次、目标设备和执行事实，任务状态与业务结论分开 |
| 离线来源 | `netops_offline_patrol_jobs`、`netops_offline_patrol_periods`、`netops_offline_patrol_source_files` | 原始采集周期、文件来源、设备绑定和分析任务 |
| 检查标准 | `netops_check_items`、`netops_check_item_versions` | 稳定业务身份与不可变版本；标准语义随版本固定 |
| Parser | `parser_template_jobs`、`parser_templates`、`netops_parser_spec_revisions` | 制作任务、候选与模板、解析方案及证据版本 |
| 运行能力 | `netops_check_item_runtime_bundles`、`netops_check_item_runtime_bundle_versions`、`netops_check_item_runtime_manifests` | 可发布资产包与执行时冻结清单 |
| 报告 | `netops_report_manifests`、`netops_report_claims`、`netops_report_content_reviews`、`netops_report_releases` | 来源、结论依据、内容复核和正式签发 |
| Workflow | `netops_workflow_runs`、`netops_workflow_steps`、`netops_workflow_plugin_versions` | 执行进度、步骤结果和插件版本 |

公文的文档、版本、操作记录由 [公文领域服务](../src/core/official_documents/)管理。自动制作检查点使用已有 ParserControlSetting，不代表可以绕过资产仓库直接修改发布状态。

## 不可变与可变数据

检查项、Parser、规则和运行包的已发布版本不能就地改写。新版本需要重新生成或复核其依赖；执行清单冻结版本及摘要，后续 Active 指针切换不应改变既有批次的证据。

原始来源、采集周期、证据用途和结论资格需要保留。新建历史分析不重置原报告，也不能升级为当前现状证明。报告对象与数据库引用须共同满足摘要和权限校验。

任务操作需要幂等键、租约与迟到结果校验。状态字段不是人工修复入口；直接 SQL 修改“完成/发布”可能留下不完整依赖或不可复现报告。

## 迁移与检查

```powershell
.\scripts\windows\bootstrap.ps1 -Action apply
```

只读取当前迁移状态：

```powershell
.\scripts\windows\bootstrap.ps1 -Action check
venv\Scripts\python.exe web/django_backend/manage.py showmigrations
```

业务迁移先创建 `django` schema；Gateway 检查当前 Alembic revision，发现未迁移时拒绝按旧 schema 继续运行。`scripts/init_db.py` 额外处理 LangGraph checkpoint 初始化。旧库接管参数 `--adopt-existing` 必须针对实际旧库判断，不能普遍替代升级。

历史迁移保留用于空库安装和旧部署升级，不属于按文件年龄清理的对象。备份与恢复须覆盖数据库和 MinIO，见 [部署说明](10_部署安装手册.md)。测试使用独立数据库；代码测试通过不代表生产资产或数据迁移已经验收。
