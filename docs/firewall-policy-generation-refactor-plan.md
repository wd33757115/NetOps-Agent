# 防火墙策略生成改造方案

更新日期：2026-09-09。状态：本轮实施与验收完成；按用户最新要求，现有回退流程和相关清单保持原实现。

## 1. 已确认的业务边界

- 目标环境默认拒绝未放行流量，本功能只生成申请所需的放行策略，不追加拒绝规则，不修改设备默认策略。
- 新版申请模型动作固定为 permit。兼容读取旧表的 action 列：空值或 permit 可接受，显式 deny 或其他动作必须说明不支持，不能静默改成 permit。
- 回退维持当前实现，不修改备份、恢复、回退清单，不增加备份绑定或验证机制。
- 暂不支持基于时间的策略。模板不提供时间字段；旧表填写了有效期等当前无法落实的设置时，应明确提示不支持，不能忽略后按永久策略导出。
- 地址归属与规则合并均要求精确计算，不遍历大网段中的每个 IP，不使用抽样、近似范围或未经证明的汇总。
- 增加逐设备策略计划预览，保留人工修订入口；修订后重新执行校验。
- AI 可辅助识别申请表、解释校验结果；地址归属、路径选择、规则合并、厂商命令生成均由确定性代码执行。

## 2. 主流程

申请表 → 标准化申请 → 地址归属分段 → 路径解析 → 逐设备原始策略计划 → 等价合并 → 厂商命令 → 校验与导出。

原始申请保留原文、工作表、行号和申请标识。后续每条规则可追溯到申请行、安全域归属依据、路径及合并过程。
“原始策略计划”是在正确分段和路径解析之后、合并之前的结果，作为等价校验的参考。

## 3. 大网段安全域归属：按边界切分

### 3.1 数据结构

将单 IP、CIDR、地址范围统一转为整数半开区间 [start, end)。端口也使用区间集合。
保留用户填写形式用于预览，运算使用去重、排序后的规范区间集合。
IPv4 右边界允许 2^32 哨兵值；不能将此哨兵直接转换成 IPv4Address。
首期明确支持 IPv4，IPv6 输入给出不支持提示，不能截断或按 IPv4 处理。

### 3.2 算法

1. 在选定网络环境内，找出所有与申请地址范围相交的安全域归属前缀。
2. 收集申请范围和交集的起止边界，排序并去重。
3. 相邻边界形成小区间。每个小区间内，命中的归属前缀集合恒定。
4. 在每个小区间内按最长前缀确定归属。相同最长前缀指向不同归属时报告冲突；无归属时报告未知范围。
5. 仅当相邻区间归属和后续处理上下文一致时，合并这些区间。

这里是在完整收集边界后选择代表点查归属，不是对整个申请范围抽样。
候选前缀数为 m 时，一个连续申请范围在归属阶段最多形成 2m+1 个区间。
计算规模主要由拓扑前缀和边界数量决定，而不是申请包含的主机数量。
朴素实现的逐段归属查询仍会受 m 影响；首期使用清晰实现并设置规模限制，必要时引入前缀索引或扫描线，不先建设复杂基础设施。

### 3.3 示例

归属表：10.0.0.0/8 → 安全域 A，10.20.0.0/16 → 安全域 B。
申请 10.0.0.0/8，计算结果为：

| 地址范围 | 归属 |
| --- | --- |
| 10.0.0.0–10.19.255.255 | A |
| 10.20.0.0–10.20.255.255 | B |
| 10.21.0.0–10.255.255.255 | A |

处理 3 个区间即可，不需要遍历 16,777,216 个地址。交给厂商时按能力输出地址范围或精确 CIDR 列表，不使用会多包含地址的覆盖超网。

### 3.4 归属和路径分开

归属数据描述地址实际所属的网络区域；路由数据描述到目标地址的转发路径，两者不能混为一张表。
默认路由 0.0.0.0/0 不应自动作为所有未知地址的有效归属。
跨环境或 VPN/VRF 的重叠地址应通过 network_context 区分；首期可使用单一明确环境，但不得用设备名称排序消除冲突。

先支持管理员维护的明确路径及可验证的连接关系，校验节点存在、相邻连接、方向和完整性。
明确配置 intra_connections 时按配置建图。为兼容现有拓扑，未提供该字段时沿用旧域间互连并在预览说明，所有推导路径标记为“拓扑推导路径”，不能等同于设备实际转发验证。
同安全域是否需要策略取决于明确的设备/环境配置，不能在通用算法内假定。
缺少归属或路径时整体报告未解决范围；不能丢弃这部分申请后声称全部生成成功。

## 4. 百分之百准确的规则合并

### 4.1 不变量

以每台设备、网络环境、源/目的安全域和服务等上下文为单位，合并前后的放行集合必须完全相同：

R_before = R_after。

源地址集合与目的地址集合之间存在对应关系，不能分别求并集后直接生成笛卡尔积。
合并不跨越设备、安全域、网络环境或其他行为不同的上下文。未来新增日志、时间、NAT 等属性时，这些属性必须进入兼容性判断，未实现的属性不得忽略。

### 4.2 首期只允许可直接证明等价的变换

- 去重：删除同一上下文中完全相同的规则。
- 目的集合和服务相同时，合并源地址集合：S1×D ∪ S2×D = (S1∪S2)×D。
- 源集合和服务相同时，合并目的地址集合：S×D1 ∪ S×D2 = S×(D1∪D2)。
- 源、目的、协议相同时，合并目的端口集合。不同协议仍分别表达，不能将 tcp/udp 当成未知单一协议文本拼接。
- 同一集合中的重叠或相邻区间可以精确合并；中间有空洞则保留多个区间。

一次变换只改变一个维度，其余维度和上下文必须等价。重新建立分组键后再进行下一轮合并。
使用规范集合签名进行分组，稳定排序。只执行能减少规则数量的变换，直到稳定或达到预算。
不枚举所有源/目的子集，不追求全局最少规则。相同输入和上下文应生成相同计划、规则标识及命令顺序。

例如申请 A→X、A→Y、B→X，可表达为 A→{X,Y} 与 B→X；不能合并成 {A,B}→{X,Y}，后者新增了 B→Y。
本方案保证的是采用的变换不改变允许集合；全局最少规则数量不是验收目标。

### 4.3 验证与失败退路

- 每次变换记录输入规则、输出规则、变换种类及原始申请行引用。
- 使用独立校验逻辑检查原始计划与优化计划的双向集合差为空；采用区间集合/符号关系计算，不枚举真实 IP。
- 等价校验本身也可能产生大量片段，设置时间和片段预算；禁止超时后按“通过”处理。
- 如果优化未能完成证明，丢弃本轮优化，使用已经通过基础校验的未合并计划，并在预览中说明原因。
- 如果原始计划就有归属、路径或输入错误，必须阻断，不能借“不合并”绕过错误。
- 如果未合并计划超出目标设备容量，明确提示超限，不通过扩大范围减少条目。
- 测试层使用独立小地址空间的穷举集合校验和随机生成测试验证算法，大网段测试单独验证规模和精确边界。

## 5. 厂商命令修正

- 修复天融信、山石跨子网范围使用末段数字展开造成遗漏的问题。

- TCP 与 UDP 联合申请在标准模型中拆分协议，按适配器支持的方式输出。
- 适配器声明厂商、型号系列、软件版本及支持的地址/服务类型；先验证实际使用的华为和 H3C。
- 输出校验必须覆盖规则数量、源/目的限制、服务表达、占位符和未消费字段；不能只检查文件是否非空。
- 设备规则容量和命令长度受限时拆分为精确等价规则；无法表达时报告不支持，不能省略条件。

## 7. 逐设备策略计划预览

保留申请视角和设备视角两种查看方式，所有结论来自同一份标准计划。

| 展示内容 | 人工核对目的 |
| --- | --- |
| 实际使用的申请文件、工作表和行号 | 确认输入正确 |
| 原始源/目的地址与端口 | 核对申请意图 |
| 地址分段、安全域与匹配前缀 | 解释归属依据 |
| 经过的设备、方向和路径来源 | 解释为什么在这些设备配置 |
| 每台设备的放行规则 | 核对源/目的安全域、地址和服务 |
| 合并前后条数、对应申请、等价校验状态 | 解释优化是否保持原意 |
| 最终 CLI、适配器版本 | 核对实际生成命令 |
| 无法处理的申请及具体原因 | 避免漏配被隐藏 |

人工可编辑下载的申请表并重新上传，也可通过“不要合并”关闭合并；路径调整通过拓扑文件输入完成，再次生成完整计划。
每次输入变化产生对应计划版本并重新校验。已验证状态仅针对导出的原始内容，不适用于导出后手工修改的 CLI。
预览中的计划版本与最终下载包绑定，使用输入摘要、拓扑版本和计划摘要避免预览/导出不一致。

## 9. 验收重点

- /8 网段及其嵌套 /16、/24 能精确分段，业务实现中不遍历主机地址。
- 嵌套网段、同前缀冲突、未知地址、跨环境重叠能得到明确结果。
- 保留所有申请的源/目的对应关系；A→X、A→Y、B→X 不新增 B→Y。
- 合并前后双向差集为空；预算不足使用原始有效计划，不近似放行。
- 端口 1–65535 使用范围处理，跨子网地址不丢失，输出没有 xxx 占位符。
- 不生成拒绝策略；显式 deny、未支持的时间设置得到明确提示。
- 回退代码和相关清单保持原实现。
- 相同输入产生稳定计划；人工修改后重新验证；预览与 ZIP 内容一致。
- 原有空文件、错误文件、失败却成功和无效文件回退到样例的回归测试继续通过。
