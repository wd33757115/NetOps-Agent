# 系统管理实施计划

日期：2026-09-23。

## 范围与约束

系统管理是 admin 与 netops-config 按职责使用的入口，统一用户、用户组、应用使用授权，不作为普通业务 App 发放权限。复用现有 Django User、Group、AppGrant 与审计能力，不增加角色系统、数据库表或应用内部操作权限。管理员默认可使用已启用 App；普通用户的有效授权为直接授权与用户组授权的并集。

## 实施顺序

1. **入口与布局**：增加 `/system/users`、`/system/groups`、`/system/apps`，旧 `/users` 跳转。工作台与头像菜单显示管理员专属系统管理入口。采用全宽工作区、左侧导航、表格与编辑抽屉，适配手机、键盘和减少动效偏好。
2. **用户管理**：保留创建、编辑、启停、删除、重置密码，改造统一布局；加载失败提供重试，最后一位管理员及当前账号保护继续由服务端执行。
3. **用户组**：增加业务组创建、重命名、成员维护和删除。展示成员与所授权应用；删除说明会撤销该组的继承授权，保留账号与直接授权。默认组仅 `admin/netops-config`，不可删除或改名，admin 可管理成员；最后一名启用管理员受保护。
4. **应用授权**：独立应用列表与授权编辑器，支持用户和组授权、搜索、状态显示、有效权限及来源预览。保留已停用用户的授权记录并明确其不可登录；应用停用不清空授权。新增页面提交版本摘要，冲突返回 409，防止管理员互相覆盖；旧调用暂时兼容。
5. **验证与发布**：后端覆盖管理员边界、保留组保护、成员继承/撤销、直接权限保留、输入错误与并发冲突；前端覆盖授权来源和编辑状态。浏览器验证三页、旧地址、手机布局、入口与普通账号拒绝访问。构建并重启本地服务，更新操作说明与完成记录。

## 验收标准

- 管理员可完成“建用户 → 建组加成员 → 授权 App → 查看有效来源 → 撤销”的完整流程。
- 普通用户不能访问管理页面或接口；netops-config 仅可进入应用授权，不能管理账号或用户组。
- 移除某一授权来源时，界面能解释其他来源仍保留的权限。
- 列表加载失败不显示为无数据，保存失败保留编辑内容；删除及撤销影响明确。
- 原设备、巡检、规则、资料、问答与其他 App 的执行逻辑和数据不变。
