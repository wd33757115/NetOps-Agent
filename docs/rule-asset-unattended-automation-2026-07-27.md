# 规则资产无人值守生产与真实验收记录

## 1. 建设目标

规则资产链路以离线巡检的结构化数据为唯一生产证据，自动完成：

```text
离线数据集
→ 脱敏不可变上下文
→ ObservationContract
→ ChangePolicy
→ EventRule
→ 确定性验证
→ 历史回放
→ 资产包持久化
→ 自动发布或工程复核
→ Active Runtime
```

自动化不读取或向模型发送原始 CLI。模型仅生成候选资产，发布由本地确定性门禁控制。

## 2. 运行模式

| 模式 | 行为 |
| --- | --- |
| `disabled` | 人工触发、复核和发布 |
| `generate_only` | 自动生成、验证和回放，发布必须人工审批 |
| `auto_publish` | 严格门禁全部通过时原子发布，否则转工程复核 |

Celery Beat 每 30 秒触发一次协调任务。任务认领使用数据库行锁、租约、幂等上下文和最大重试次数，支持多 Worker 并发。

运行中的 Workflow 超过配置时间仍无进度时会被回收。默认阈值为 1800 秒，回收后根据尝试次数进入指数退避重试或工程复核，避免 Worker 异常后永久显示“运行中”。

## 3. 自动发布门禁

自动发布必须同时满足：

1. 来源为已完成的离线巡检任务。
2. 至少覆盖两个独立采集周期和两个设备。
3. 上下文是不可变的结构化数据集上下文。
4. 隐私检查通过，且不包含原始 CLI。
5. Contract、Policy 和 EventRule 资产包完整。
6. synthetic validation 全部通过。
7. 历史回放范围完整、存在真实命中且碰撞数为 0。
8. 预估每日事件量不超过配置上限。
9. Critical 规则仅在管理员明确允许时自动发布。

任一条件不满足都不会降级绕过，而是保留候选、验证报告、回放报告和阻断原因，转交工程师处理。

## 4. 人工接管

工程复核页面必须同时提供：

- 脱敏样本和字段画像；
- ObservationContract、ChangePolicy、EventRule 候选；
- 本地验证结果；
- 历史变化命中数、碰撞数和事件量估算；
- Workflow 各阶段状态与耗时；
- 接受、驳回和修订入口；
- 原子发布与审计原因。

运行时仅解析 `active` 资产。候选、待审批或已驳回资产不会影响生产巡检。

## 5. 通用事件治理

ChangePolicy 可以覆盖需要比较的结构化字段，但 EventRule 只对具有可执行事件语义的字段生成：

- 软件、固件、硬件身份变化；
- 明确状态转换；
- 带阈值或设备阈值的数值异常；
- 具有治理映射的故障、健康和恢复语义。

容量字段在没有阈值时、自由文本字段在没有语义映射时，不强制要求 EventRule。生成规划与 Runtime Resolver 共用同一判断函数，避免控制面显示完整、运行时仍误报规则缺口。

## 6. 浏览器真实验收

验收命令为 `show version`，来源任务为：

```text
offline_job_id: offline-4f2e92af9c4c4857bdec
context_id: rule-context-ded1de41f1b546e4bc3c
seed_id: 82fac433-da08-4860-aacb-5ac93497f6a7
workflow_run_id: 86e021e6-a39f-4dec-9498-558356c05f1c
bundle_id: dd872cac-ef60-40b1-a9c7-0ac12e5db24f
```

输入证据覆盖 4 份命令输出、2 台设备和 2 个采集周期。Workflow 七个阶段全部完成，总耗时约 6 分 34 秒，生成：

- 1 个 ObservationContract；
- 8 个 ChangePolicy；
- 4 个 EventRule。

历史回放扫描到 49 条变化，碰撞数为 0。样本期间没有发生版本生命周期事件，因此真实命中数为 0。`auto_publish` 门禁按设计拒绝自动发布并转工程复核，没有把“未发生事件”等同于“规则错误”。

工程师在浏览器检查候选、回放和证据后接受候选并原子发布。发布后验证结果：

```text
结构化采集：就绪
变化分析：就绪
事件评估：就绪
运行时阶段：3/3
规则链缺口：0
```

## 7. 本次真实测试修复

1. 资产包持久化后主动刷新命令生产单元，消除“Workflow 已完成但 Policy/Event 仍显示未开始”。
2. 已发布资产切换类型时不再复用上一类型的缓存行，消除短暂的 `undefined` 字段闪烁。
3. 生成规划与 Runtime Resolver 统一事件规则适用性，修复非事件字段被错误判定缺少 EventRule。
4. 证据不足的自动化任务计入“转人工”，控制面不再静默遗漏。
5. 增加规则 Workflow 超时恢复、退避重试和最大尝试门禁。

## 8. 发布与运维要求

- FastAPI、Celery Worker 和 Celery Beat 必须同时运行。
- 自动化策略变更必须记录管理员和变更原因。
- 生产环境应监控 Beat 心跳、活动 Workflow 数、超时回收数、转人工数和自动发布数。
- 首次启用建议使用 `generate_only`，在真实回放样本覆盖稳定后再切换为 `auto_publish`。
- 要验证完全无人值守发布，需要准备至少一组包含真实事件变化且无冲突的双周期样本；本次 `show version` 因零真实命中，正确走了保守的人工复核路径。
