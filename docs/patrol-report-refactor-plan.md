# 巡检报告重构实施方案

实施基线：用户修改并确认的 v1 CLI 证据模板。原文件保留，运行时模板打包进代码资产。离线巡检是本轮验收入口。

## 模块边界

1. `report_templates`：内置模板与管理员导入模板；文档结构校验、稳定版本、内容摘要。仅允许登记的数据控件，拒绝外部链接、嵌入对象和危险字段。
2. `report_view`：冻结巡检事实到模板字段的确定性映射；保留设备与槽位/通道身份，缺值明确显示，禁止伪造阈值和健康结论。
3. `report_evidence`：文本差异片段、结构化对象定位、原始行号与标红；无法唯一定位时明确回退，提供完整命令追溯。
4. `report_renderer`：读取用户模板，填充标量、重复表格与 CLI 对照，保持模板排版；不调用模型。
5. `report_drafting`：本地白名单汇总包、发送预览、快照与模板版本绑定、一次性确认、限额、模型输出校验和人工采纳。默认不开启。
6. 独立 API 与报告生成对话框：模板选择/导入、本地报告下载、证据预览与全文切换、可选 AI 预览和采纳。

## 约束

- 现有用户未提交改动保留；只删除确定无调用的旧路径，不直接重写无关巡检执行或规则资产模块。
- CLI、配置、日志、标识、哈希及本地路径不进入 AI 请求。模型只处理批准的汇总包和固定提示词，不提供工具访问。
- 默认不发起真实模型请求；失败、取消或未采纳时仍可本地导出。
- 判定结论、数量、阈值、证据与人工签署不能由 AI 更新。
- 用户只能访问自己有权限的巡检任务。模板配置与导入限制管理员；普通用户仅使用已发布模板。
- 数据库结构变更以 Alembic 迁移实施；AI 预览与草稿存储按用户和任务隔离，多进程共享。

## 验收

- 单元测试：40 接口只摘异常对象、多通道、重复数值、无基线、对象模糊、恢复事件、正常值变化、同对象多个事件、文本增删与上下文、缺阈值/单位。
- 模板测试：用户模板保留、重复行、全部控件被处理、空值、危险导入、完整命令可追溯。
- 隐私测试：AI 关闭不请求；秘密不出站；过期/跨用户/变更预览拒绝；重复确认不重发；输出越权/错引用拒绝；本地导出在 AI 失败后可用。
- 前端验证：TypeScript、组件测试、构建、实际离线结果下载与 Word 逐页检查。
- 现有巡检/报告相关测试回归；记录本轮不具备在线设备的验证范围，不将离线验证宣称为在线实测。

## 已实现的使用流程

在离线巡检的已完成任务中点击报告下载，打开“生成巡检报告”。默认选择内置 v1 模板，本地生成完整 Word；管理员可以下载模板、保留控件修改后导入。导入内容按摘要保存为独立版本，现有版本不覆盖。

CPU、内存、风扇、电源、光功率和接口计数按观测对象展开，缺字段标为未提供。接口输入错误数和输出错误数不合成缺失的 ERR_PKTS；内存 bytes 字段明确显示 B。没有新事件的当前风险也进入原文核对；未判定项目不写成正常。

附录 F 展示已有文本变化的原文片段，附录 G 展示事件和当前风险关联的对象片段。保留原始行号和快照号，界面可按需查看全文。接口别名、通道表和接口简表有确定性定位；不支持或有歧义的格式提示核对全文。恢复事件没有重新判定基线时不自动标红。原文差异颜色与异常红色分别处理。

“导出报告与证据包”包含 Word、全部字段观测 CSV、引用的完整 CLI 和 manifest.json。manifest 保存模板摘要、分析版本、观测摘要、原文摘要及快照索引。索引按命令快照汇总，避免每个字段重复一行。

## AI 请求与人工采纳

入口开关默认关闭。打开开关也不会调用模型，只有“确认发送并起草”会发送预览里的请求。用户可选概述、变化总结，系统只包含相应的必要汇总事实。

- 概述：执行数量、判定覆盖、受控分类的风险统计及其限制。
- 变化总结：文本采集/比较/变化数量，结构化变化与故障/恢复事件数量及其限制。
- 不复制风险说明、规则表达式、模板正文或设备自由文本。少量受控分类名称由代码提供。
- 固定提示词位于 `report_drafting.SYSTEM_PROMPT`。请求总消息限制为 6000 个 UTF-8 字节，输出限制 1200 tokens；超限不截掉必要事实，直接提示使用本地报告。
- 预览 15 分钟有效，绑定用户、任务、事实、模板摘要和模型配置。服务器保存预览，重复确认不重复发送。
- 仅允许两个叙述字段。校验段落、长度、引用和数值，拒绝越权字段；这些校验不能替代人工的语义复核。用户审阅并采纳后才用于导出，结论、表格、限制和证据由本地程序保留。
- 模型错误只返回通用提示，继续允许本地导出。测试只调用模拟模型，没有发送实际巡检数据。

模板中的新增业务字段需要在展示投影和 `report_assets/bindings.json` 中登记；已登记字段可通过导入模板改变布局或列顺序。AI 辅助设计模板时也应保留这些控件。

## 真实数据暴露并修复的问题

文本哈希观测过去使用空主键，不同配置和日志命令共享状态标识。去重后 7 项文本可能只剩 1 项，甚至将 `display startup` 与 `display logbuffer level 4` 配对。现在文本实体和比较键均包含规范化命令名，旧观测读取时也按命令重建比较键；结构化字段的跨命令语义保持原规则。数据库集成回归验证两个命令分别比较，只有实际变化的命令产生变化事实。

报告出口另行检查比较引用的设备、命令和周期。错配的旧结果返回明确的重新分析提示，不输出误导性的 Word。原始历史结果不改写，复检生成独立任务。

比较阶段持久化实际比较过的文本命令集合，报告只读取与选定分析匹配且唯一的已完成阶段记录，按命令去重统计。没有保存该统计的历史任务明确提示覆盖未知，不再把“没有变化记录”误写成“未比较”。

接口简表摘录只保留表头及目标接口行，避免带入 VLAN、聚合口或下一张表；多行光模块输出仍按对象和通道裁剪。持续风险没有新增事件时，也会在本任务唯一匹配的基线中查找原文；基线没有独立异常判定时不标红。证据标题与表格保持相邻，没有文本差异时不单独占一个空附录页。

在线巡检和规则资产验证仍在使用的旧报告渲染函数保留；离线报告出口已切换到新模块，避免误删共享逻辑。

## 巡检详细数据 Excel（2026-09-09）

- 在“生成巡检报告”中增加“导出详细数据 Excel”。报告与证据包同时附带 `patrol-details.xlsx`，Word 交付清单列明该文件。
- 一项检查项一个工作表，使用检查项名称；结构化数据列为设备 ID、命令、问题描述及该任务冻结的检查项标准 Value，保持定义顺序。保留正常记录，变化字段标红；问题描述复用 Word 报告的同一投影，不重新计算健康结论。
- 按设备、命令、对象标识及观测维度配对基线和当前数据。缺少基线、标识冲突、版本字段不一致时明确说明，避免错误配对和误报删除。
- 文本型检查项逐行并排显示完整基线和当前 CLI，变化行标红；超长单行分段保存，避免 Excel 单元格长度截断。提供冻结前三列和表头、自动筛选、交替底色、适应列宽及打印重复表头。
- 结构化表只写完整标准记录，不从 StateObservation 反拼记录，也不追加 CLI 兜底行。读取任务固定的检查项及适配器版本，对完整解析记录执行原规则并验证质量；错误的身份字段、失效的版本关联不得用观测值掩盖。
- “问题描述”只复用报告结论。未关联命令、缺失定义、比较限制、缺失设备阈值集中放在“导出说明”；完整原文继续通过任务原始输出及证据包下载。
- 修复 H3C `display cpu` 适配器把槽位数字同时写入 scope/scope_id 的错误，scope 使用声明的槽位类型；补充身份字段枚举校验。保持当前 CPU 检查项的 5 分钟评估口径，不伪造缺失阈值。重新分析生成独立的“巡检详细数据修正版”任务，原任务保持原始证据。
- 全程本地生成，不调用 AI。导出先检查任务访问权限，再读取选定周期的快照；字符串按文本写入，长整数保留精度。
- 验证：92 项相关后端测试通过；此前的前端/BFF 下载接口保持兼容。重新分析后的真实 BFF 下载和证据包导出通过，共 15 个工作表。CPU 仅一条标准记录，光功率 40 条、接口运行信息 73 条；恢复描述与 Word 一致，变化字段单独标红。所有工作表渲染检查，Excel 原有导出入口同步使用本实现。
