# 巡检规则自动制作与授权发布

本轮需求：人工定义检查项、人工确认命令与检查项的关联；其余制作流程自动推进，允许人工随时暂停接管。管理员启动或授权后，验证通过自动发布。

## 使用方式

1. 在“检查标准”中定义检查项及判断标准。保存时由服务器固定该版本引用的标准语义，生成输出契约；无需另行刷新契约。
2. 导入设备命令样本，人工确认命令属于哪个检查项。确认关联后自动启动后台制作，离开页面不会停止任务。
3. 在命令详情查看“自动制作”：检查规则 → 解析验证 → 标准数据 → 设备适配 → 自动发布。也可以为已有人工关联的命令点击“开始自动制作”。
4. 管理员启动即授权该任务验证后自动发布。获得配置权限的操作员可以制作和接管，发布需要管理员点击“授权自动发布”。授权限定检查项版本、命令和设备范围，有效期 24 小时；范围变化需要重新授权。
5. 点击“暂停并接管”，等待当前步骤结束后，可使用现有解析器编辑界面或“人工编辑字段转换”。继续后重新检查样本、解析方案和模板版本，修改失效的下游结果会重建；人工修改的字段转换保留并重新验证。

## 自动化边界

- 检查项、判断含义和命令关联始终由人工确定，AI 不得擅自改写。
- 变化规则和事件规则按检查项语义确定性编译，同一版本优先复用同一套规则。可选标准字段也准备相应规则，运行包按实际输出选择需要的规则。
- 解析方案和 TextFSM 复用现有有界生成、修复及独立复核。字段转换优先确定性匹配，不能通过时调用 AI，单个候选最多三轮；实际样本执行失败会进入修复反馈。
- 当前脱敏正样本逐份运行生产解析器和标准转换；负样本不得输出业务数据。没有正样本、标准数据不完整、输入变化、复核失败都会保留诊断并停止推进。
- 发布前检查整个候选依赖图、输入摘要、设备范围、规则兼容性及现有运行包影响；发布后再次按正式门禁装配并激活运行包，成功后才显示“已发布，可用于巡检”。
- 正在使用的解析器/规则依赖若会被替换，必须具备已有版本切换流程要求的验证证据；不能证明兼容时停止自动发布。自动授权不等于绕过验证。
- 自动发布记录为 `administrator_delegated_automation`，保留授权人和任务标识，不伪造工程师复核签名。原手工制作、复核和审批接口保留。

## 持久化与恢复

任务检查点保存在现有 `ParserControlSetting`，不需要数据库迁移。资产仍由原 Parser、检查项目录、规则和运行包仓库管理。

Celery `netops.ai` 执行 `advance_command_autopilot`；Beat 每分钟恢复排队任务。单步租约 20 分钟，工作进程硬超时早于租约；异常中断转为待处理，避免盲目重复发布。暂停同时使解析子任务的标识失效，迟到的方案和生成结果不能覆盖新一轮工作。

资产发布沿用各仓库事务，整条链路不是一个跨仓库事务。意外中断时已发布资产可能保留；继续时重新检查并复用，只有运行包激活成功才标记任务完成。

部署需更新前端构建、FastAPI、AI Worker 和 Beat。无需自动启动或重新发布历史制作任务。

## 验证

新增测试覆盖重复启动、暂停与迟到结果、子任务失效、手工修改、授权过期/范围变化、操作员越权，以及使用隔离 SQLite 数据库和真实 TextFSM/标准转换的完整发布链路。前端覆盖暂停、等待接管、管理员授权按钮及操作员限制。

回归入口：`tests/unit/test_command_autopilot.py`、`tests/unit/test_command_autopilot_integration.py` 及前端自动制作组件测试。完整发布测试覆盖复用已发布 Parser、发布待审批 Parser，以及证据型运行包；当前执行结果见维护记录，不以旧测试数量证明目标环境已就绪。

真实外部模型的生成质量取决于设备样本与模型服务；本次自动化测试不调用生产模型，也不对现有生产资产进行发布试验。
