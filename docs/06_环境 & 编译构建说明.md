# 开发与构建

核对日期：2026-09-06。从仓库根目录执行命令，使用独立开发环境。

## 依赖角色

Python 3.11、Node.js 22、Docker Compose v2。前端使用已提交的 `package-lock.json`，安装执行 `npm ci`。

| 依赖文件 | 使用位置 |
| --- | --- |
| `requirements-core.txt` | 确定性巡检和控制任务 Worker |
| `requirements-gateway.txt` | 核心业务网关，包括表格导入支持 |
| `requirements-ai-worker.txt` | AI 任务 Worker，包含文档生成依赖 |
| `requirements.txt` | 本地完整 Python 应用环境与 AI 网关 |
| `web/django_backend/requirements.txt` | Django BFF |

Qdrant、Langfuse 等可选依赖见对应 requirements 文件和 `pyproject.toml` 的可选组。Streamlit 已退出项目，不再安装或启动。

## Windows 本地启动

首次创建配置；已有 `.env` 时跳过复制。

```powershell
Copy-Item .env.example .env
.\scripts\test\install.ps1
.\scripts\test\start.ps1 -SkipLangfuse
```

启动脚本会执行 PostgreSQL 与 Django 迁移，再启动核心 Worker、AI Worker、Beat、FastAPI、Django 和 React。默认 React 运行生产构建预览，修改前端后需重新构建；调试热更新使用：

```powershell
.\scripts\test\start.ps1 -SkipLangfuse -DevMode
```

已自行启动必需中间件时可加 `-SkipMiddleware`。`-AllowNoDocker` 只跳过 Docker 探测，不能代替数据库或队列服务。

| 入口 | 默认地址 |
| --- | --- |
| React | `http://localhost:3000` |
| Django BFF | `http://localhost:8001` |
| FastAPI 本地调试 | `http://localhost:8000` |

日志在 `.runtime/test/logs/`，进程记录在 `.runtime/test/pids.json`。启动器文件可能包含环境变量，排障时只分享经过检查的业务日志。

```powershell
.\scripts\test\stop.ps1
```

`-KeepMiddleware` / `-KeepLangfuse` 可保留对应 Docker 服务。启动/停止脚本会管理该项目进程，不用于多个开发实例共用端口的场景。

## 手动安装与迁移

```powershell
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe -m pip install -r web/django_backend/requirements.txt
npm --prefix web/react_frontend ci
venv\Scripts\python.exe scripts/migrate_db.py
venv\Scripts\python.exe web/django_backend/manage.py migrate --noinput
```

Django 默认使用 PostgreSQL 的 `django` schema。历史 SQLite 迁移脚本仍用于旧环境迁入，不能把复制 SQLite 文件当作当前数据库初始化。

网关启动会检查业务 schema 是否最新，不替代迁移步骤。只验证 schema 时使用 `python scripts/migrate_db.py --check`。`--adopt-existing` 仅用于已有 Alembic 前时代数据库的接管，不能作为普通安装的默认参数。

账号管理使用 Django。本地需要演示账号时可执行 `seed_auth_users`；该命令会重设同名账号密码和分组，不能对已有正式账号重复运行。正式管理员使用 `createsuperuser` 或现有用户管理流程。

## 独立调试与检查

前端仅访问同源 `/api`，由 Vite/Nginx 转发至 BFF。生产 API 基址构建参数是 `VITE_API_BASE_URL`；旧的 `REACT_APP_API_URL` 不生效。

```powershell
npm --prefix web/react_frontend run dev
npm --prefix web/react_frontend run check
.\scripts\validate_ps1.ps1
```

如果单独启动后端，必须同时保证需要的 Worker 队列和 Beat 可用。Windows Worker 使用 `solo`，并发为 1；不要通过给 solo 设置更大的 concurrency 假设获得并发。

`deployment/Makefile` 是额外的 GNU Make 入口，可从根目录执行 `make -f deployment/Makefile help`，或 `make -C deployment help`。`up-all` 只启动 core profile；AI 需要叠加配置。生产部署见 [部署安装](10_部署安装手册.md)，回归范围见 [维护与验证](maintenance.md)。
